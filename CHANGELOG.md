## [Unreleased]

### Added
- **The Workplace Shell's root class, first part** (ADR-0129): `WPObject` and its metaclass `M_WPObject` as guest code in the SDK — `sdk/include/wpobject.idl`, `sdk/wps/wpobject.c`, built with `somidl` into `libwps.a` (`$(OS2_LIBWPS)`). Setup strings (`wpSetup`, `wpSetupOnce`, `wpScanSetupString`; `TITLE`, `OBJECTID`, `DEFAULTVIEW` and the style keys), titles, styles, default views, object IDs, errors, `wpAllocMem` / `wpFreeMem`, `wpSaveString` / `Long` / `Data` and their restores (kept with the object; OS2.INI comes with `WPAbstract`), `wpDelete` / `wpConfirmDelete` / `wpFree`, locking, and `wpclsNew`, `wpclsQueryTitle` / `Style` / `DefaultView`, `wpclsInitData`. `samples/wps_object_test` subclasses it in IDL (31 checks, GCC and clang).
- **`somidl`**: an interface declared only forward is an object type; a parent from another IDL file is included by its `filestem`.
- **`WPFolder`** (ADR-0129 addendum): a directory's Workplace object with its content list (`wpPopulate`, `wpQueryContent`, `wpAddToContent` / `wpDeleteFromContent`, `wpContainsFolders`, `wpQueryFldrFlags`); `wpclsNew` makes new files and folders in a folder, named by their titles; `wpQueryFolder` and `wpclsQueryFolder`; deleting a folder deletes everything in it (`wpDeleteContents`). `wps_object_test` has 76 checks.
- **`WPTransient`, `WPFileSystem`, `WPDataFile`** (ADR-0129 addendum): a file's or directory's Workplace object (`wpclsQueryObjectFromPath`, one per file, returned locked), its names, attributes, size, dates and types (`.TYPE`), its state in the file's extended attributes (`.LONGNAME` for a title no file name can be, `WARPINE.WPSTATE` for the rest), a title change renaming the file and `wpFree` deleting it; `WPTransient`'s objects are never stored. `wpclsQueryObject` now returns the object locked, as the Reference says. `wps_object_test` has 64 checks.
- **`DosSetPathInfo` level 2** sets extended attributes from an `EAOP2`'s `FEA2LIST` (a list not well formed: `ERROR_EA_LIST_INCONSISTENT`, `oError` naming the entry; a `fea2_list` fuzz target), and **`DosQueryPathInfo` level 5** (`FIL_QUERYFULLNAME`) gives a fully qualified name. The SDK has `EAT_BINARY` / `EAT_ASCII` / `EAT_MVMT` / `EAT_MVST`, `ERROR_INVALID_EA_NAME`, `ERROR_EA_LIST_INCONSISTENT` and `ERROR_EAS_NOT_SUPPORTED`.
- **`WinCreateObject`, `WinDestroyObject`, `WinSetObjectData`** (PMWP 281, 251, 250; ADR-0130): Workplace objects created, changed and deleted by handle and ID from any program. The host records the class and queues the title and setup string in the user profile; `libwps` makes the object (`wpSetupOnce`) or applies what was queued (`wpSetup`) when a program that has the class asks for it (`wpclsQueryObject`), in that process or a later one. `CO_FAILIFEXISTS` / `CO_UPDATEIFEXISTS` / `CO_REPLACEIFEXISTS`. `wpScanSetupString` gives a key's last occurrence, so later setup wins. `wps_object_test` has 50 checks; its "save" run creates an object a later "load" run makes. A `wps_setup` fuzz target (ADR-0112 addendum) found two flaws in joining queued setup strings, both fixed. 1038 entry points.
- **`WPAbstract`, objects kept in the user profile** (ADR-0129 addendum): stored when made and on every change (`WPObject`'s setters call `wpSaveDeferred`; its `wpSaveState` / `wpRestoreState` keep its title, style, view and object ID), with a handle (`wpQueryHandle`); `wpclsQueryObject` gives an awake object or awakens a stored one; `wpFree` removes it; an object ID names one object. **`WinQueryObject`** (PMWP 252) finds a stored object's handle by its ID. `wps_object_test` has 41 checks, and a "save" run whose object a later "load" run finds. 1035 entry points.
- **SOM TypeCodes** (ADR-0128; SOM Programming Reference; Warpine's own ordinals 3109–3120, ADR-0123): `TypeCodeNew` for every kind (structs, unions, enums, sequences, arrays, pointers, self-references, foreign types, object references, bounded strings and the basic kinds), `TypeCode_alignment`, `_copy`, `_equal`, `_free`, `_kind`, `_param_count`, `_parameter` (an `any` pointing at the parameter; `TypeCode::Bounds` out of range), `_print` (the `TypeCodeNew` call that makes it), `_setAlignment` and `_size`, and the `TC_*` constants. Sizes and alignments are those of the SDK's i386 C types; the TypeCodes live in guest memory in Warpine's own layout, answered from the kernel's own records. `c_som_test` checks the sizes against each compiler's `sizeof` (36 checks). 1034 entry points.

- **Shared muxwait semaphores across processes** (ADR-0050 addendum): named and `DC_SEM_SHARED` muxwait lists live in the session's semaphore segment, so another process opens them by name or handle, waits on them and adds or deletes records. Their members are shared events or mutexes. The segment's slots grow to 2 KB (version 2). `shsem_test` has 33 checks, 24 in its child.

- **Extended attributes by handle**: `DosSetFileInfo` level 2 sets them and `DosQueryFileInfo` level 3 returns them (the VFS remembers the path each file was opened by); level 2 of both queries reports the true size of the file's EA list. New sample `ea_test` (30 checks, GCC and clang).

- **Large files** (DOSCALLS 981–989): `DosOpenL`, `DosSetFilePtrL`, `DosSetFileSizeL`, `DosSetFileLocksL`, `DosCancelLockRequestL` and the `DosProtect*L` forms; 64-bit sizes at levels 11–13 of the file-information calls and in `DosFindFirst`'s `FILEFINDBUF3L` / `4L`. The SDK declares them, with `FILESTATUS4L` and `FILELOCKL`. New sample `largefile_test` (40 checks, GCC and clang). 1047 entry points.

### Fixed
- **`DosQueryPathInfo` level 3 wrote past a too-small buffer**: it never read the `FEA2LIST`'s `cbList`, so a short buffer was overrun in the program's own memory. It now gives `ERROR_BUFFER_OVERFLOW` and writes nothing, and a malformed `GEA2LIST` gives `ERROR_EA_LIST_INCONSISTENT` with `oError` (the `fea2_list` fuzz target covers the new parser).
- **`DosEnumAttribute`** had its reference types swapped (`<bsedos.h>`: 0 is a handle, 1 a path) and wrote entries in neither `DENA1`'s nor `DENA2`'s layout; it now writes linked `DENA2` entries, by handle or by path.
- **A GDB interrupt (Ctrl-C) stops a program spinning in guest code** (ADR-0104 addendum): the stub only set a flag the vCPU reads between runs, so a loop that never called Warpine was never stopped (the stub gave up after 2 s); it now kicks every vCPU out of the guest. `c_gdb_test spin` and a raw-RSP integration test check it.
- **`DosSetPathInfo` level 2** returned success without setting the extended attributes, and **`DosQueryPathInfo` level 5** was refused (`ERROR_INVALID_LEVEL`).

### Changed
- **`somBuildClass` initializes the class object**: a metaclass's own `somDefaultInit` now runs on the class objects it builds, before `somClassReady`, as `somNew` on a metaclass already did.

### Security
- **The SOM kernel's guest strings** (names, `somPrintf`'s format and `%s` arguments) stop at Warpine's protected memory, so neither `somPrintf` nor a TypeCode copies or prints it.

### Added
- **The SOM class manager's registry calls** (SOM Programming Reference; Warpine's own ordinals 3410–3414, ADR-0123): `somSubstituteClass` (the lookups by a class's name give an immediate child instead, and `<Class>New()` makes it) with the SDK's `SOM_SubstituteClass(Old, New)`, `somMergeInto` (another class manager becomes `SOMClassMgrObject`), `_get_somRegisteredClasses` (a sequence of every registered class) and `_get_somInterfaceRepository` (NULL: there is none). `som_idl_test` has 59 checks. 1022 entry points.

### Changed
- **The Workplace Shell is built on SOM** (ADR-0127): XPCOM, listed as an alternative, is no longer considered.
- **A confined process runs with the GPU drivers' shader disk caches off** (ADR-0111 addendum): `ci/check_desktop.sh` with `strace` on a Wayland / PipeWire / NVIDIA desktop showed the driver trying its cache in the home directory, which the sandbox keeps out of reach on purpose. Warpine now runs itself again at its start with `__GL_SHADER_DISK_CACHE=0` and `MESA_SHADER_CACHE_DISABLE=true` when they are missing (unless `WARPINE_SANDBOX=off`), so the drivers stop trying. The script reports that cache and `/proc` thread naming as expected refusals.

### Security
- **The audit's remaining findings**: an API called with a stack pointer where the host cannot build its frames (next to Warpine's protected memory, in a shared block not held, or with an unreadable return address) now ends the process as a fault does, before the API runs, instead of a host panic at one of about a dozen places that built a frame there; exception dispatch with no room for the handler's call ends the process as an unhandled exception, and an unwind with no room for its next handler stops there. Byte copies of guest-named memory (`guest_read_bytes`, used by about a hundred calls) and guest strings no longer read Warpine's protected memory.

## [0.0.19] - 2026-11-25

### Added
- **`ci/check_desktop.sh`** checks the sandbox and the seccomp deny lists on a real desktop: four samples (PM and VIO windows, PM and VIO sound) run once confined and once with `WARPINE_SANDBOX=off`, and the runs are compared (end marker, the SDL drivers used, warnings only the confined run has, and with `strace` the calls only it had refused). Warpine now logs the SDL video and audio drivers it uses at `info`.
- **The resolver is fuzzed** (ADR-0112 addendum): the address and domain-name parsers move out of `tcpip_util.rs` into `inet_names.rs`, which builds alone, and the new `resolver` target feeds DNS messages, the hosts, networks and `resolv.conf` files, and names and address strings to them (a packed name must expand back to itself, `dn_skipname` must agree with `dn_expand`).

### Changed
- **CI pulls a published image instead of building it in every job** (ADR-0106 addendum): the new `ci-image.yml` workflow publishes the pinned image to GitHub's registry when its inputs change, `ci/image.digest` pins it by digest, and the test and fuzz jobs pull it (building it as before when there is no pin or the pull fails). The image build retries its downloads and no longer asks rustup to check for its own update, the call behind two failed runs.

### Fixed
- **SIGTERM left a process alive while it waited for standard input** (found by `ci/check_desktop.sh`): `DosRead` of redirected or terminal standard input made a blocking `read()`, which the process's end could not interrupt, so a program waiting for input nobody fed outlived its forced end. It now waits in 100 ms steps, as pipe reads do. New integration test `test_sigterm_ends_a_process_waiting_for_standard_input`.
- **`dn_expand` overflowed on a name that pointed backwards** (found by the `resolver` target in its first minute): the length a name takes was worked out from the end of the pointed-to name as well, even when a pointer had already set it, and underflowed when that lay before the name's start; a debug build ended the calling process. Release builds wrapped and threw the value away.
- **Memory just handed to a thread could lose its pages** (ADR-0114 addendum), which CI once showed as a thread created suspended that never ran after `DosResumeThread`: a thread's end and `DosFreeMem` freed memory before giving up its page states, so a block given to another thread at that address in between was written "not present"; two threads could write the allocator's pending page-table changes out of order; and a thread could look at the tables while another was still writing a batch. Page states now go first, pending changes are written in order under one lock, and a sync waits for a batch in progress.

### Security
- **The audit's Medium findings**: `somApply` applied any of SOM.DLL's thunks as a root method, its own too, and so could apply itself without end; now only the root classes' methods. A call into the guest (`somDispatch` dispatching itself, a window procedure sending to itself) nests at most `MAX_CHAIN_NESTING` (512) host frames, and one with no room for its frame below the guest's stack is skipped as if it returned 0 instead of panicking. `getservbyname` / `getservbyport` copy libc's shared result under the services lock. A new process id skips ids still in use when numbering wraps (ADR-0036 addendum): a live process's, and holders in the shared-memory table.
- **The audit's Low findings**: `somVaBuf_add`, `somApply`'s arguments, `writev`, `send`'s byte-wise fallback and `dn_expand` / `dn_skipname` no longer copy Warpine's protected memory back to the program; a `somVaBuf`'s capacity is the kernel's record, not its header's; `somApply` does not apply a root method of more arguments than a call passes (`somInitClass`, `somInitMIClass`); guest values no longer overflow in `somApply`, `somVaBuf_create` or `dn_comp`'s `dnptrs` walk (at most 1024 entries); `DosRead` checks the buffer before reading, so a refused read takes nothing; a queue holds at most 65,536 elements and 256 MB (`ERROR_QUE_NO_MEMORY`); a new shared block is zeroed under the table's lock; the resolver waits for each server at most its time, whatever arrives meanwhile, with random query ids.
- **A process could keep a shared block after letting it go** (ADR-0049 third addendum, found by a security audit of v0.0.18): a page fault on the block racing its free by another thread mapped it again for good; `recv` / `recvfrom` let the kernel write a buffer checked before a wait, by then perhaps a block another process had been given; and a look at the session's table taken before a free and stored after it put the block back among those API calls may use. The page entries, the holds and the table now change in order under the table's lock, a stale look is dropped, and sockets receive into host memory and copy out through the checked path (one receive takes at most 64 KB).

## [0.0.18] - 2026-11-25

### Added

The SDK gains `struct netent` and the resolver's declarations. `netutil_test` has 39 checks. 1017 entry points.
- **SOM dynamic dispatch** (ADR-0126): `somDispatch`, `somClassDispatch`, `somDispatchV` / `L` / `A`, `somApply`, `somVaBuf_create` / `_add` / `_get_valist` / `_destroy` and `somvalistGetTarget` / `SetTarget`. `somidl` writes an apply stub for every method, so a class built from its bindings can be called by name from a `va_list` or a `somVaBuf`, any argument and result type included; root methods are applied directly. The SDK gains `TCKind`, `somVaBuf` and the `_somDispatch` / `_somClassDispatch` varargs forms. `som_idl_test` has 49 checks. 1003 entry points.
- **CONFIG.SYS and profiles are fuzzed** (ADR-0112 addendum): their parsers move into `config_sys_parse.rs` and `profile_text.rs`, which build alone, and get the fuzz targets `config_sys` and `profile` (a profile must survive being written back).
- **CONFIG.SYS's `THREADS=` checked against more sources**: they agree with Warpine's 64 to 4095 (64 by default) for Warp 3 / 4 and ArcaOS; IBM's Command Reference itself is still not available as text outside install media, so the item stays open. The sources are in the README.
- **`KbdStringIn` follows the keyboard's mode**: ASCII mode edits with Backspace, ends at the turnaround character `KbdSetStatus` set and echoes only with echo on; binary mode keeps every byte, never echoes, and ends when the buffer is full. The keyboard now starts as the KBD reference says, in ASCII mode (with echo on), and `KbdGetStatus` reports it so. `vio_kbd_test` has 59 checks.
- **Extended LIBPATHs are inherited**: a child starts with its parent's BEGINLIBPATH and ENDLIBPATH, and `DosSetExtLIBPATH` expands `%BeginLIBPATH%` / `%EndLIBPATH%` and keeps to 1024 bytes. `libpath_test` has 17 checks and a child.

### Changed
- **The keyboard starts in ASCII mode with echo on**, as the KBD reference names ASCII the default; `KbdGetStatus` reported binary mode with echo off before, while `KbdStringIn` behaved as ASCII mode anyway.

### Fixed
- **A long host name overran the TCP/IP record buffer**: `gethostbyname` stored the name in a 256-byte buffer without a limit, and the servent shared that buffer, so a name over 24 bytes overwrote it and a longer one the memory after. Each record now has its own region and names are cut to fit.
- **`DosRead` of a file returned `NO_ERROR` when it could not write the program's buffer**: it now returns `ERROR_INVALID_PARAMETER`, as for a pipe.

### Security
- **API calls are held to shared-memory holds** (ADR-0049 second addendum): a buffer in a shared block the calling process does not hold, or a read-only block it would write into, fails the call instead of being read or written; a block another process has just given is found by reading the session's table again. Calls that only read a buffer accept a block held read-only. 16-bit programs were checked to reach none of the shared arena (new sample `ne_arena_test`); the earlier note that they reached all of it was wrong.

The SDK's `os2/sub.h` declares them, with `KBDHWID`, `VIOPALSTATE`, `VIOOVERSCAN` and `VIOINTENSITY`. New sample `vio_kbd_test` (46 checks, keys piped in by its test). 949 entry points.

### Changed
- **A process can have 736 threads** (was 738): the shared arena's page tables take two paging blocks (ADR-0115 addendum).

### Fixed
- **`WinSetCp` refused without saying why**: it now records `PMERR_RESOURCE_NOT_FOUND` for a codepage it does not take (0 included) and `PMERR_INVALID_HMQ` for an unknown queue.
- **The ULS return codes were Warpine's own** (1, 2, 8, 10): UCONV now returns `<ulserrno.h>`'s (`ULS_INVALID` 0x2040E, `ULS_BADOBJECT` 0x2040F, `ULS_BUFFERFULL` 0x20412), so a program comparing with them sees its errors; an unknown codepage name is `ULS_INVALID`.
- **`sock_errno` returned the bare BSD numbers** (35 for a blocked call) instead of `SOCBASEERR` plus them (10035, `SOCEWOULDBLOCK` in `<nerrno.h>`), so a program comparing with the `SOCE*` constants never matched.
- **A menu template could nest submenus without bound**, one recursion per 16 bytes of a template up to 64 KB: the parser now stops at 16 levels (`MAX_MENU_DEPTH`), and reads the template as a byte slice.
- **`getprotobyname` / `getprotobynumber` always failed** while counted as implemented: they now answer from Warpine's protocol database (ip, icmp, tcp, udp).
- **`VioScrollUp` / `VioScrollDn` scrolled whole lines and ignored limits beyond the screen**: they moved full rows whatever the left and right columns, did nothing when the bottom row was past the screen (so the usual `0, 0, -1, -1, -1` did not clear it), and cleared the area for 0 lines. After IBM's reference they now scroll only the rectangle, take a corner or count beyond the screen as its edge, and scroll nothing for 0 lines.

### Security
- **Shared memory access is enforced** (ADR-0049 addendum): the shared arena goes through per-process page tables, so a program's code reaches only the blocks it holds, read-only when it got or was given one without `PAG_WRITE`, and a block it let go traps (`XCPT_ACCESS_VIOLATION`); `DosQueryMem` reports arena blocks from the session's table. When a parent reaps a child, the shared blocks and semaphores only that child held are gone at once (ADR-0050 addendum). `shmem_test` grows to 31 checks + 18 in the child.
- **A seccomp filter per process role** (ADR-0124, `src/syscall_filter.rs`), behind Landlock: every Warpine process refuses debugging other processes, new namespaces, `bpf` / `io_uring` / `userfaultfd` / `perf_event_open` and the key ring, administration calls and typing into its terminal (`EPERM`), and is killed on a 32-bit or x32 system call; the desktop server also cannot start programs or use KVM. `WARPINE_SANDBOX=off` turns it off with Landlock; `warpine --syscall-check guest|desktop-server` reports it. New dependency `seccompiler`.

## [0.0.16] - 2026-11-24

### Added

The headline row now sums all 1230 Warp 4 exports (63 %), and the os2386.lib row keeps its earlier numbers. A version that lacked a module shows a dash. `gen_compat` has 12 tests.
- **The SOM entries IBM's Reference documents that the kernel lacked**: `SOMClass`'s `somRenew`, `somRenewNoInit`, `somRenewNoZero` and `somRenewNoInitNoZero` (objects in the caller's memory), `somGetMemberToken`, `somGetMethodIndex`, `somGetNthMethodInfo`, `somGetMethodData`, `somGetNthMethodData` and `somGetMethodDescriptor`; `SOMObject`'s `somCastObj` / `somResetObj`; `SOMClassMgr`'s `somGetInitFunction`; `somMainProgram` and `somEnvironmentEnd`. ### Fixed
- **UCONV and MDM at the ordinals of Open Watcom's import libraries** — Warpine's own numbers differed: `libconv.lib` has `UniUconvToUcs` at UCONV 2, `UniUconvFromUcs` 3, `UniFreeUconvObject` 4 and `UniMapCpToUcsCp` 10 (Warpine served them at 3, 4, 2 and 6), so a program linked with the library called the wrong function. ## [0.0.10] - 2026-11-22

### Added
- **OS/2's page states for allocated memory** (ADR-0114). `DosAllocMem` honours its flags: memory without `PAG_COMMIT` is reserved and faults until `DosSetMem` commits it; `PAG_READ` alone makes read-only pages; `DosSetMem` commits (zeroed), decommits and changes access; `PAG_GUARD` makes guard pages, whose first touch raises `XCPT_GUARD_PAGE_VIOLATION`; `DosQueryMem` reports the real state. At ring 3 a thread's stack is committed as it grows (`STACK_SPARSE`, the default of `DosCreateThread`; `STACK_COMMITTED` commits it whole), and a thread that runs out gets `XCPT_UNABLE_TO_GROW_STACK` instead of silently overwriting the memory below its stack. - **Free memory faults** (ADR-0114). Memory freed with `DosFreeMem`, and memory never allocated, raises `XCPT_ACCESS_VIOLATION` when touched, as on OS/2, instead of being silently readable and writable. `DosQueryMem` reports free memory as `PAG_FREE` and a program's code as read-only.

### Changed
- **At most 226 threads per process** (was 191): the paging arena now also holds the process's page tables, and each thread's paging block is a page smaller (ADR-0114).

### Deprecated
- **`WARPINE_RING=0`** (ADR-0113): this is the last release that can run programs at ring 0; the variable, and the ring-0 defences with it (the paging watch), go in the next one.

- **A program's own breakpoint instruction** (`INT3`, or `INT 3`) raises `XCPT_BREAKPOINT` to its exception handlers, as on OS/2, with EIP past the instruction so a handler can continue. Before, it ended the process at once with exit code 0 and no exit list; unhandled, it now ends the process like any other exception (exit list with `TC_EXCEPTION`, exit code 1). When a program activated its own frame just as another program's activation reached the desktop server, the server's `Deactivate` arrived afterwards and won, and both programs then disagreed with the server about which window was active (`pm_xproc_test` failed now and then under load). Reports of the active frame are now numbered (desktop protocol version 9). An API call's change is reported before the call returns, and a program ignores a `Deactivate` that answers an older report.

- **Exception handlers read the wrong registers from `CONTEXTRECORD`** (ADR-0101).
  - Warpine laid out 0x88 bytes of floating-point state where IBM's structure has 0x6C, so `ctx_RegEip`, `ctx_SegCs`, `ctx_RegEsp` and the rest were read from other registers' places.
  - The record now follows `<bsexcpt.h>`, 0xB0 bytes with `ctx_SegGs` at 0x70.

### Security
- **EXE objects are checked at load** (ADR-0094): an EXE whose objects leave the program area (64 KB–16 MB) or overlap is refused with a message. Before, such objects were loaded over Warpine's structures and the API thunks, and one outside guest memory panicked the loader.
- **Guest paging is guarded** (ADR-0088). The guest runs at ring 0 and could rewrite its new page tables or load CR3 / CR0. The host never follows its tables and accepts a CR3 only as a whole, page-aligned block in the allocator's region. A watch thread kicks each vCPU every 250 ms, and a thread whose paging was changed ends as a trap; its exit list still runs, on repaired tables with the half-delivered fault dropped. Crash reports show CR3 and whether the tables are intact. Sample: `samples/paging_abuse_test`, a hostile guest built five ways.
- **No endless spin on memory past guest RAM** — 1,000 accesses in a row past the guest's memory (a wild page-table entry or loop) end the thread as a trap; before, a guest could keep its process spinning for good.

### Fixed
- **Programs with large static data lost some of it** (ADR-0094). Warpine kept its GDT, IDT, TIB, PIB, thread-local page and information segments at `0x80000`–`0xBFFFF`, inside any program with more than about 450 KB of static data. The program's bytes there were overwritten, or read as another thread's. These structures now live in a system area at `0x01800000`. Sample: `samples/bigdata_test`.
- **`SIGQUIT` no longer ends Warpine with a core dump** (ADR-0093): Ctrl+\\ at a terminal used to kill the process.
- **EA sidecars** (filesystems without extended attributes) — a rename lost a file's EAs and a delete left them behind; the `.os2ea` folder showed in directory listings, was reachable by programs, and kept its directory from being deleted. `DosCopy` copied no EAs at all.
- **A termination during an access past guest RAM lost its exit list** — KVM completes such an access on the next run and overrode the registers Warpine had just pointed at the exit-list routine; the access is now completed at once (`finish_mmio`).
- **PMWIN and PMGPI calls by name** (ADR-0087) — `DosQueryProcAddr` and `WinLoadProcedure` found no PMWIN or PMGPI call by name; `build.rs` now reads the names from the dispatchers. By ordinal, these modules now find only the calls Warpine implements (`ERROR_PROC_NOT_FOUND` for the others), as the registry modules do.
- **Exit lists run on thread 1** (ADR-0087), as the Control Program Guide describes: a `DosExit(EXIT_PROCESS)` on another thread asks thread 1 to run them, as a fault there already did. A guest `HLT` ended the process at once; it now runs the exit list like a trap (`TC_TRAP`), and so does a failed `KVM_RUN` on thread 1 (`TC_HARDERROR`).

### Removed
- **4OS2** — the 4OS2 sample and the files fetched or patched from it are gone, including copies of 4OS2 and Open Watcom sources that had been committed without the notices their licences require. The built-in `CMD.EXE` is Warpine's shell: the default `COMSPEC` is `C:\CMD.EXE`, the text-mode integration tests and the README's text-mode screenshots use it, the VIO samples generate their 32-bit `bsesub.h` from the local Open Watcom install at build time (`samples/bsesub32.mk`), and the DLL-loader tests use Warpine's own `samples/dll_noinit` (ADR-0075).

### Security
- **`DosEditName` overflow** — a target length of 0 made `cb_target - 1` overflow: a panic in a debug build, a write past the program's buffer in a release build. The result and its NUL must now fit, else `ERROR_BUFFER_OVERFLOW` (ADR-0079).
- **A pipe's output is bounded** — the built-in CMD.EXE holds at most 16 MiB of a command's output for the next one, reading and dropping the rest, so a guest program cannot grow the host's memory without bound through a pipe (ADR-0077).
- **No host working directory from a guest path** — `DosExecPgm`, `WinStartApp` and CMD.EXE set a child's host working directory from the host's own joined with a guest path; they now pass OS/2 current directories, which the child applies through its own VFS (ADR-0077).
- **Shell redirection stays inside the drives** — the built-in `CMD.EXE` opened a redirection target that did not exist yet (`> file`) through the guest's path string as a host path, so a guest could write host files outside its drives through `CMD.EXE /C … > path`; it now creates the file through the VFS, and a path outside the drives is an error. Creating any new file through a dangling symbolic link, which would place it at the link's target, is refused too, `DosOpen` included (ADR-0075).

### Fixed
- **`WinFillRect` colours** follow the presentation space's colour table: after `GpiCreateLogColorTable(LCOLF_RGB)` a colour of 0 is black, not the background colour (ADR-0086).
- **`DosReadQueue`'s wait flag** was inverted: `DCWW_WAIT` now waits for an element and `DCWW_NOWAIT` returns `ERROR_QUE_EMPTY` (ADR-0086).
- **Built-in modules are always loaded:** `DosQueryModuleHandle("DOSCALLS")` and the like return a handle, and `DosLoadModule` knows REXX, REXXAPI and PMWP as built-in. `DosQueryProcAddr` by ordinal on a registry-dispatched built-in module finds only what Warpine implements, so a C runtime probing for `DosOpenL` falls back to `DosOpen` (ADR-0086).
- **Writes into a closed pipe looked successful** — a guest's `DosWrite` to its standard output, when that was a host pipe or file, ignored write errors, so a program piped into a reader that stopped early wrote forever; it now gets `ERROR_BROKEN_PIPE` (ADR-0082).
- **A malformed executable crashed Warpine** — an entry or stack object number of 0 made the loader index its object table at `0 - 1`; it is now refused with a load error (ADR-0080).
- **A file copied onto itself was emptied** — `DosCopy("A.TXT", "a.txt")` truncated the file; it is now `ERROR_ACCESS_DENIED`. `DosCopy` also copies to another drive now.
- **Names differing only in case** — creating, copying or renaming onto a name that exists in another case made a second file; it now reaches the existing entry, so a dangling link of another case is refused as well.
- **Files made outside the VFS were not found for up to 2 s** in another case (after a shell redirection, for example).
- **`DosEditName`** edits names beyond ASCII by character.
- **Child processes start in their parent's current directory** — a program started by `DosExecPgm`, `WinStartApp` or CMD.EXE now gets its parent's current drive and directories, and `WinStartApp`'s start directory becomes its current one; before, every child started at `C:\`.
- **`CD` and `DosSetCurrentDir`** take only an existing directory and collapse `.` and `..`; `\` and `C:\` name the root (`CD \` did nothing before).
- **`DosQueryCurrentDir`** returns `\` separators, not `/`, and refuses a drive that is not mounted.
- **Piped standard input** — `DosRead` on a pipe or file no longer echoes the bytes to standard output or turns CR into CR LF.
- **`warpine CMD.EXE /C …`** with the command in several host arguments ran nothing; they are joined into one command line.
- **Redirection** — after a redirected command the shell's output went back to the screen even inside a script run with its own redirection.

### Changed
- **The built-in CMD.EXE is split into modules** — `cmd.rs` and `cmd/` (`parse`, `env`, `builtins`, `external`, `input`).
- **The guest crates stay GPL-3.0-or-later** — OS/2 programs built with `warpine-os2-sys` / `-rt` / `warpine-os2` are covered by the GPL; the question ADR-0074 left open is settled (ADR-0076).
- **`VER` names the release** — the built-in `CMD.EXE`'s `VER` prints the latest release's version number after the shell's name (`… [Builtin CMD.EXE] version 0.0.6`).
- **Goal stated** — Warpine is an OS/2-alike API and its runtime environment: a familiar, robust API set as the foundation of a Free Software platform, not a clone; compatibility with legacy applications is done case by case, and anything needing proprietary intellectual property is skipped (`README.md`, `CLAUDE.md`).
- **Licence: GPL-3.0-or-later** — Warpine's own code, samples and guest crates move from GPL-3.0-only to GPL-3.0-or-later (ADR-0074, superseding ADR-0002): every source file carries `SPDX-License-Identifier: GPL-3.0-or-later` (the files that had no header now have one), and `Cargo.toml`, the guest crates' manifests and the cargo-deny policy say so. Vendored third-party material keeps its own licence.

### Security
- **Guests could change the host environment** — the built-in CMD.EXE's `SET` changed the Warpine process's own environment, so a guest could set `LD_PRELOAD` to a library it wrote and have every later child process load it as native code, and `SET` listed the host's environment (tokens, agent sockets) to the guest. The shell now keeps its own OS/2 environment, passed to its programs through `WARPINE_OS2ENV`; `clippy.toml` forbids changing the process environment anywhere (ADR-0066).
- **Guests could reach host Unix sockets** — `socket()` passed any address family to the host, and `bind` / `connect` / `sendto` the guest's raw address, so a guest could talk to the session D-Bus, X11, `docker.sock` or Warpine's own desktop and pipe sockets, and create socket files outside the drives. Only `AF_INET` sockets with a 16-byte `sockaddr_in` are allowed now (ADR-0066).
- **Host panics on a guest stack pointer** — an API call or a hardware exception with an ESP too low for the frames the host builds below it panicked the host process; it now ends the guest process as a fault does. Huge container column widths no longer overflow the layout arithmetic (ADR-0066).
- **Supply chain** — `vendor/setup_watcom.sh` downloads a pinned, dated Open Watcom snapshot over HTTPS and checks its SHA-256 before extracting; `samples/4os2/fetch_source.sh` checks out and verifies the full 40-character commit; `vendor/unifont/unifont.hex` is now GNU Unifont 17.0.03 exactly, from the signed release, with its provenance recorded; the Rust guest crates pin a dated nightly; a `deny.toml` policy (crates.io only, allowed licences, advisories) runs in the pre-commit hook and at release; `rustix` is updated (RUSTSEC-2026-0486); tracked build outputs (`.o`, `.res`) are removed (ADR-0066).
- **No decompressors in `lx_link`'s ELF reader** — `cargo audit` reported RUSTSEC-2026-0344 (high): `ruzstd` 0.7.3, pulled in by `object` 0.36's default features, can exhaust memory on a tiny compressed input. `object` is now built with `read_core`, `elf`, `archive` and `std` only, so `ruzstd` and `flate2` leave the build (86 → 78 crates); compressed sections are refused. `lx_link` also no longer allocates an unreadable section's header-given size as zeros: uninitialized sections are bounded to 256 MB, and any other unreadable section is an error.
- **Host paths of drive files stay in their drive** — resolving an OS/2 path to its host file (for `DosExecPgm`, `WinStartApp`, CMD.EXE, the MSG calls) skipped the drive's sandbox check, so `..` on a drive whose directory folds case in the kernel, or a symbolic link, could lead outside it (ADR-0063).
- **DLL search stays in its directories** — a module name with a path (`../x`, `C:\x`, `a/b`), `..` or control characters was put into a host path, so `DosLoadModule` could load a file outside the program's directory and `C:\OS2\DLL`; only plain module names are searched now (ADR-0062).

### Changed
- **Closing the PM desktop or a VIO / text window** sends KILLPROC and runs the exit list instead of exiting at once; the program ends with code 1 within the grace period. `SIGINT` and `SIGTERM` are caught and go through the exit list.
- **The samples are built with a current Open Watcom snapshot.** The vendored snapshot of March 2026 had a start-up bug (Open Watcom #1649, fixed 2026-08-11) that lost `argv` and the environment of every program built with it; Warpine's entry stack was already right.
- **The pre-commit hook runs the checks inside a capped systemd scope** (`MemoryMax` 24G, no swap, `TasksMax` 4096, overridable) where a user systemd instance exists, so a runaway test ends inside its own cgroup instead of exhausting the machine (ADR-0031).
- **New built-in module slots** PMSPL (`PMSPL_BASE` 18432) and PMCTLS (`PMCTLS_BASE` 19456); the API stub area grows to 20480 bytes. PMCTLS ordinals come from the Open Watcom import library.
- **Resizing repaints less** — a window whose class lacks `CS_SIZEREDRAW` repaints only what a larger size uncovers, and nothing when it shrinks, as in PM. Built-in controls and dialogs still repaint whole.
- **`WM_SIZE` reports the client's own size**, which differs from the frame's surface once frame scroll bars are present.
- **One handle space for files and pipes**, lowest free number first, as on OS/2. Pipe handles started at 0x1000, which broke Open Watcom C runtimes.
- **`EXEC_ASYNC` / `EXEC_ASYNCRESULT`** return the child's process id in `RESULTCODES.codeTerminate`, as the CP Reference says.
- **`gen_api validate-doc`** lists name differences acknowledged by a `# NOTE:` on the def line (such as DOSCALLS 75, `DosQueryFileMode16` / `DOS16QFILEMODE`) with their note instead of reporting them as mismatches to investigate on every pass.
- **API stub area** grows to 18432 bytes for the new PMSHAPI (`PMSHAPI_BASE` 16384) and HELPMGR (`HELPMGR_BASE` 17408) modules.
- **Built-in scroll bars look different** — arrows, shaft and slider, greyed when disabled; the `pm_controls_test` golden signatures were regenerated.

### Fixed
- **File times** are reported in local time, as OS/2 keeps them (they were UTC), and clamped to the `FDATE` range 1980–2107: a year after 2107 no longer wraps into the 7-bit field, and one before 1980 no longer keeps its month and day.
- **`DATETIME.timezone`** from `DosGetDateTime` is minutes **west** of UTC, as the Control Program Reference defines it; it had the opposite sign.
- **Imports by name from built-in modules** other than DOSCALLS (an LX import by name, now also `DosQueryProcAddr`) added the module's ordinal base twice and reached the wrong stub.
- **A suballocation pool freed with `DosFreeMem` without `DosSubUnsetMem`** stayed registered, so a new pool at the same address failed.
- **Named-pipe session directories of killed Warpine processes** stayed in the runtime directory; they are swept at the next session start by liveness.
- **Integration tests wrote into the user's runtime directory** — Warpine processes started by the tests got a temporary `XDG_DATA_HOME` but the real `XDG_RUNTIME_DIR`, so named-pipe and thread-session directories of test runs landed in `/run/user/<uid>`; every test helper now gives them a temporary runtime directory too.
- **A program that starts itself could exhaust the host** — nothing limited how deeply Warpine processes start one another; a self-starting test program made about 230 processes before the out-of-memory killer stopped them. Fixed by the process nesting limit.
- **`DosPutMessage` was at the wrong ordinal** — MSG.3 is a 16-bit entry; the 32-bit one is MSG.5. **`DosGetMessage`** read its arguments one place off and left the caller's stack 4 bytes off: Open Watcom's `DosGetMessage` stub passes the message segment as an extra first argument (found in Open Watcom's own library code, not in OS/2's).
- **`GpiQueryTextBox` returned the top-right and bottom-right corners swapped** (`TXTBOX_TOPRIGHT` is 2, `TXTBOX_BOTTOMRIGHT` 3).
- **`WinLoadString` misread string tables built by `wrc`** — it took the bundle's codepage for the first string's length and counted the NUL in it; a missing string now sets `PMERR_RESOURCE_NOT_FOUND`.
- **`WinSetWindowULong(QWL_STYLE)` did not change the style**; it stored a word that `WinQueryWindowULong` never read.
- **The `WC_SPINBUTTON` atom in the developer guide** was 0xFFFF000F; the code and the header say 0xFFFF0020.
- **`WinFillRect` into a memory presentation space** drew into the window instead of the bitmap selected into the PS.
- **A blocked pipe read held the handle table**, so every writer blocked too; pipe and socket descriptors leaked into child processes; `DosClose` of an unknown pipe handle succeeded.
- **Wrong ordinals in API doc comments** — ten comments named the wrong ordinal, `DosKillProcess` (235) among them.
- **Exception handlers of other threads** — `DosSetExceptionHandler`, `DosUnsetExceptionHandler`, `DosRaiseException`, `DosUnwindException` and hardware exceptions used thread 1's TIB for every thread, so all threads shared one handler chain: an exception could reach another thread's handler. Each thread now has its own chain, in its own TIB. A handler record outside the program's memory returns `ERROR_INVALID_PARAMETER` instead of crashing Warpine.
- **Continuing after `DosRaiseException`** — a handler returning `XCPT_CONTINUE_EXECUTION` resumed the caller with EBX, ESI, EDI and EBP zeroed; the caller's registers are now kept. Sample `xcpt_thread_test`.
- **Pointer coordinates of client windows** — mouse messages to a frame's client were relative to the frame, so x was off by the border width (2 pels with a sizing border), and a window holding the capture got desktop coordinates; both are now relative to the window.
- **`QMSG` layout** — `WinGetMsg` / `WinPeekMsg` wrote the message position as two SHORTs where `QMSG.ptl` is a POINTL of two LONGs, and the time and position were always 0.
- **`WC_SPINBUTTON` atom** was 0xFFFF000F instead of 0xFFFF0020; a test now checks every `WC_*` atom against the toolkit headers.
- **`DosQuerySysInfo(QSV_TIMER_INTERVAL)`** returned 32; the value is in tenths of a millisecond, so it is now 320.
- **Wrong ordinals in the reference manual** for `DosFlatToSel`, `DosSelToFlat`, `DosSetFileLocks` and the `DosSub*` calls, and calls listed that did not exist yet.
- **Tests wrote to the user's drive C** — the integration tests and the mock loader of the unit tests used `$XDG_DATA_HOME/warpine/drive_c`; they now use temporary directories and `target/test-drive-c`.
- **Named semaphores** — a name given at creation was ignored, so opening by name never worked (and failed with `ERROR_FILE_NOT_FOUND` instead of `ERROR_SEM_NOT_FOUND`); a mutex created owned belonged to thread 1 whichever thread created it.
- **Muxwait lists of mutexes** were treated as events, so `DosWaitMuxWaitSem` never took the mutexes; `DosCreateMuxWaitSem` now checks the semaphore types, duplicates, the 64-record limit and its flags.
- **Huge GPI string counts** — `GpiCharString` / `GpiCharStringAt` used the program's count unchecked, so a count such as 0xFFFFFFFF made Warpine allocate gigabytes; they now draw at most 4096 bytes and fail for a negative count.
- **Strings at the top of the address space** — `VioWrtTTY`, `VioWrtCharStrAtt`, `UniUconvToUcs` and socket sends kept reading after the first byte outside guest memory, so an address near 4 GiB overflowed (a panic in debug builds) and a huge count meant billions of failing reads; they now stop at the first unreadable byte.

### Changed
- **A single click on a frame's system-menu icon opens the system menu** instead of starting a drag; a double click still closes the frame.
- **Country and codepage follow the host locale** — a program now starts with the OS/2 country code and process codepage of the host locale, as on an OS/2 installation in that language (`ja_JP` → country 81 / CP932, `de_DE` → 49 / CP850, `C` → 1 / CP437), instead of always 1 / CP437; the VIO screen and new message queues follow it. `WARPINE_COUNTRY` and `WARPINE_CODEPAGE` override it (e.g. `WARPINE_CODEPAGE=437` for programs that draw with CP437 box characters). The fixed US setting had been a workaround for the Watcom C runtime hanging at start-up with non-US countries, which the NLS ordinal fix removed. The integration tests and the screenshot helper pin 1 / 437.
- **Calls with a handle that is no window now fail** — `WinShowWindow`, `WinUpdateWindow`, `WinInvalidateRect`, `WinStopTimer`, `WinSetCapture`, `WinSetDlgItemText`, `WinDismissDlg`, `WinSetAccelTable`, `WinSetWindowULong` / `WinSetWindowUShort`, `WinQueryWindowRect` (it reported 640 × 480), `WinQueryWindowPos` and `WinEnableWindow` returned TRUE for such a handle; they return FALSE, and `WinCreateWindow` with a bad parent creates nothing, as the PM reference says.
- **Caret positions, clicks and word wrap are measured in the queue's CJK face** — text controls measured with the process codepage's face while drawing in their queue's; the two now agree.
- **Invalid window handles** — `WinSetWindowPos`, `WinSetWindowText` and `WinPostMsg` now return FALSE for a handle that is not a window (recording `PMERR_INVALID_HWND`); `WinPostMsg` used to drop such a message into another queue.
- **Closing a message box** — the close button and Alt+F4 end a message box with `MBID_CANCEL` even when it has no Cancel button ("whether or not a cancel button existed", the `WinMessageBox` reference); Esc still cancels only a box with a Cancel button.
- **CJK face of control, title and menu text** (`mod.rs` `Painter`, `surface.rs`, `sdl_renderer.rs`) — built-in controls, title bars and menus drew CJK characters in the face of the process codepage, so a window whose queue was set to another codepage with `WinSetCp` (e.g. CP949 in a CP932 process) showed its Hangul and hanja in the Japanese face. They now use the face of the window's (or frame's) queue codepage, as GPI text already did with its presentation space's.
- **Message order in a queue** (`pm_input.rs`) — `WinGetMsg`, `WinPeekMsg` and the modal dialog loop handed out a queue's messages in posting order, so a `WM_TIMER` or `WM_PAINT` could come before a later posted message or before input. They now follow the PM Reference: posted messages, then keyboard and mouse input, then `WM_PAINT`, then `WM_TIMER` (`WindowManager::next_queued`, one function for all three). `pm_typeahead_test` checks the order from the guest (5 checks; the previous build fails the new one).
- **The pre-commit hook lints the test code** — `githooks/pre-commit` ran only `cargo test`, although the README said it also ran clippy; it now runs `cargo clippy --all-targets -- -D warnings` as well, so lints in tests fail the commit. The 26 lints already in test code are fixed.
- **`WinMessageBox` is a modal PM dialog** (`pm_msgbox.rs`) — it used SDL's native message box on the GUI thread, which froze the whole desktop (every window, repaints, timers) until it was closed. It is now a dialog built in memory — the caption, the text wrapped at word boundaries, the push buttons of the `MB_*` set with the `MB_DEFBUTTON*` default — centred on the desktop and run by the `WinDlgBox` modal loop: only its owner's frame is disabled, and the owner's window procedure keeps getting its messages. A push button returns its `MBID_*`; Esc and closing cancel a box that has a Cancel button. Scripted sessions can answer message boxes. New sample `pm_msgbox_test` (7 checks) and golden `pm_msgbox_test`; `GUIMessage::ShowMessageBox` is gone.
- **Message queues follow the PM reference** (`pm_win.rs`, `pm_types.rs`) — `WinDestroyMsgQueue` was a stub that kept the queue; it now destroys the calling thread's own queue and its pending messages (FALSE for another thread's queue or an invalid handle), after which the thread can create a new one. `WinCreateMsgQueue` returns `NULLHANDLE` when the thread already has a queue, and `WinPostMsg` returns FALSE when there is no queue to post to. `pm_list_test` checks the lifecycle (17 checks).
- **Menu bars are shown through `WM_UPDATEFRAME`** (`pm_win.rs`) — `WinLoadMenu` used to attach the new menu to the frame at once and `WinCreateMenu` never did. Following the PM reference, both now create the menu as an `FID_MENU` child owned by the frame (found with `WinWindowFromID(frame, FID_MENU)`), and the frame shows its topmost `FID_MENU` menu when sent `WM_UPDATEFRAME(FCF_MENU)` (handled in `WinDefWindowProc`). Destroying the shown menu takes the bar away. `FCF_MENU` menus are `FID_MENU` windows too. `pm_menu_dlg_test` replaces its menu bar that way (9 checks, now asserted by `gui_menu_dlg_test_replaces_the_menu_bar`).
- **SDL3 instead of SDL2, with no `unsafe`** (`Cargo.toml`, `src/gui/`; `sdl2_renderer.rs` / `Sdl2Renderer` / `Sdl2TextRenderer` renamed to `sdl_renderer.rs` / `SdlRenderer` / `SdlTextRenderer`, and the `sdl2` names in the console and keyboard code to `sdl`; `build.rs` no longer looks up SDL2 with pkg-config) — the PM desktop and the VGA text window use sdl3-rs 0.22 through its safe API only; `src/gui` and `mmpm.rs` are `#![forbid(unsafe_code)]`. The `unsafe_textures` feature (which dropped the texture-lifetime check) is gone, as are the raw calls for the wake-up event, mouse capture and the byte view of the desktop buffer. Building needs `libsdl3-dev` instead of `libsdl2-dev`. GUI output is unchanged (golden tests) and composite times are unchanged; checked by hand on X11 and Wayland (input, clipboard, window management, audible audio).
- **Audio plays on the main thread** (new `src/gui/audio.rs`) — SDL3 audio objects cannot leave the main thread, so MMPM/2 and `DosBeep` hand PCM data to an `AudioService` and the PM / VGA loop plays it through SDL3 audio streams, which also convert formats (the SDL2 conversion code is gone). WAV files are decoded in Rust (uncompressed PCM and float; compressed WAVs, which `SDL_LoadWAV` accepted, are refused). `MCI_SET` volume changes now reach a playing sound. Headless runs have no audio output.
- **PM drawing is rasterised on the calling thread** (new `src/gui/surface.rs`) — GPI primitives, `WinFillRect` and built-in controls draw straight into the shared surface of their frame (`WindowManager::surfaces`) instead of sending one `GUIMessage` per primitive to the GUI thread, which now only composites. The pixels exist when the call returns, which `GpiQueryPel` and destination-dependent mixes need; drawing outside `WinBeginPaint` / `WinEndPaint` now shows up without waiting for another repaint. `GUIMessage` keeps only clipboard, mouse-capture and message-box requests. Guest-side `pm_bench` rates are unchanged for boxes and lines (~28 µs per call) and about 13 % lower for text, which is now rasterised inside the call.
- **The PM compositor redraws only what changed** (`sdl2_renderer.rs`, new `src/gui/damage.rs`) — the desktop buffer is kept between frames; damage comes from dirty windows (mapped to their frame) and frames that moved, changed chrome or disappeared, and only those rectangles are redrawn and uploaded (`Texture::update`). Frames hidden by an opaque frame above are skipped, pixels are copied row by row, and title bars, menu bars and pull-downs are pre-rendered per frame and re-rendered only when they change. On SDL's `dummy` driver (release build, 1024×768) a composite takes 0.37 ms instead of 0.69 ms during `pm_bench` and 0.61 ms instead of 0.90 ms while dragging a window, which also composites only when the pointer moves (121 instead of 182 composites in 5 s). Frame statistics now report the share of the desktop redrawn.
- **Per-thread glyph cache** (`font.rs`) — each character's face, advance and coverage bitmap are cached per thread; drawing and measuring text no longer lock a global cache or clone an `Arc` per glyph, nor resolve the face again.
- **Resizing keeps window content** — `FrameBuffer::resize` keeps the bottom-left part of the old picture instead of blanking the window until the application repaints.
- **PM event loop blocks instead of polling** (`renderer.rs`, `message.rs`, `sdl2_renderer.rs`, `pm_types.rs`) — the GUI thread used to sleep 8 ms per pass (up to 8 ms added latency, ~125 wake-ups a second when idle) and read the host clipboard on every pass. It now blocks until input, a queued GUI message, a window marked dirty, the next frame or the next scripted step (`GuiWake`, woken by `GUISender::send` and `WindowManager::mark_dirty`); idle, it wakes 10 times a second. `PresentBuffer` no longer composites immediately: composites are coalesced to at most one per 16 ms frame. The host clipboard is read at start-up and on clipboard-update and focus-gained events. On SDL's `dummy` driver an idle session uses about half the CPU it did.
- **`create_gui_channel` returns a `GUIReceiver`** and `PmRenderer::frame_sleep` is replaced by `install_waker` + `wait_for_work`.
- **Menu bar is frame chrome** (`pm_types.rs`, `sdl2_renderer.rs`, `mod.rs`) — the menu bar and open pull-down are drawn by the compositor from window state instead of into the client's FrameBuffer, and the client area now ends below the menu bar (`WindowManager::layout_frame` / `attach_menu`). `WinLoadMenu`, `WinSetWindowPos` and drag-resize re-lay out the frame; the client receives `WM_SIZE` + `WM_PAINT` when its size changes.
- **GPI text is positioned by its baseline** — `GpiCharString` / `GpiCharStringAt` treat `y` as the text baseline, as PM defines it (previously the bottom of the character cell).
- **`sdl2` crate 0.37 → 0.38.**

### Fixed
- **Ending a thread ended the whole program** — `DosExit(EXIT_THREAD, rc)` and a thread function returning now end only that thread (new `src/loader/threads.rs`); the process ends when its last thread ends, with that thread's result code. `DosWaitThread` follows the Control Program Reference (`DCWW_WAIT` / `DCWW_NOWAIT`, 0 for any thread, an ended thread reported at once; it used to give up after a second), `DosKillThread` really ends the thread (it reported success while the thread ran on), and created threads get ids from 2 with a complete TIB / TIB2 (the exception chain was 0, not the end marker). Their stack and TIB are freed when they end and their vCPU is reused, and `DosCreateThread` returns an error instead of stopping Warpine when it runs out of resources. The text-mode front end no longer ends the process as soon as thread 1 stops. Sample `thread_exit_test`.
- **4OS2 `cls` printed `[2J`** — escape sequences were not interpreted (see "ANSI escape sequences" above).
- **`echo text > file` and `prog > file` left the file empty and hid the prompt** — `DosDupHandle` only handled pipes; it now duplicates files (sharing the file pointer) and the console, `DosRead` / `DosWrite` / `DosClose` / `DosSetFilePtr` / `DosQueryHType` and the others follow redirected standard handles, and `DosExecPgm` hands a redirected handle to the child.
- **4OS2 hung after every external program** — `DosWaitChild(DCWA_PROCESSTREE)` locked the process table twice and deadlocked.
- **A waiting `KbdCharIn` / `KbdStringIn` polled forever at the end of piped input** — the process now ends with exit code 0 (Warpine's choice; the KBD reference lists no end-of-input error).
- **`VioGetAnsi` wrote 4 bytes into a `USHORT`**, and a TAB in `VioWrtTTY` printed a glyph instead of moving to the next multiple of 8.
- **Socket options used Linux's numbers** — `setsockopt` / `getsockopt` passed OS/2's BSD option numbers (`SOL_SOCKET` 0xFFFF, `SO_REUSEADDR` 4, …) straight to Linux; they are now translated, and options whose value differs in layout are refused with `SOCENOPROTOOPT`.
- **Host buffer over-read in `setsockopt` and `sendto`** — both passed the guest's length to Linux although Warpine may have copied fewer bytes; they now pass the length actually copied.
- **`socket_test` and `thread_test` could not be built from a fresh checkout** — `socket_test` needs Watcom's C99 mode (`-za99`), and `thread_test` had no Makefile.
- **`VioCheckCharType` at the wrong ordinal, and DBCS cells never recognised** — it was served at VIOCALLS 39, which does not exist; Open Watcom's `os2386.lib` has it as `VIO16CHECKCHARTYPE`, ordinal 75 (`<bseord.h>` `ORD_VIOCHECKCHARTYPE`). The VIO screen's codepage also stayed 437 whatever `DosSetProcessCp` set, so neither `VioCheckCharType` nor the text renderer paired DBCS bytes; it now follows the process codepage. `VioWrtCellStr` (VIOCALLS 10) was a stub and now writes cells, continuing on the next row and stopping at the end of the screen. `samples/dbcs_test` invented the ordinal 39 import and declared the call `_System`; it now builds against 4OS2's `_Pascal` headers and passes 15/15. The unused import pragmas in 4OS2's `viowrap.c` now carry the library's ordinals too.
- **NLS calls at the wrong ordinals** — Warpine's NLS table did not match the toolkit's `<bseord.h>` or Open Watcom's `os2386.lib`. NLS 6 answered `DosQueryDBCSEnv` (called by the Watcom C runtime at start-up) with country information; NLS 5 chose between `DosQueryCp` and `DosQueryCtryInfo` by buffer size; NLS 8 served the DBCS query instead of `DosQueryCollate`. NLS 5–8 are now `DosQueryCtryInfo`, `DosQueryDBCSEnv`, `DosMapCase` and the new `DosQueryCollate`; they honour the `COUNTRYCODE` codepage, and a short buffer gets what fits plus `ERROR_NLS_TABLE_TRUNCATED` (a short `DosQueryDBCSEnv` buffer used to get error 113). The invented `DOSCALLS.373` / `DOSCALLS.397` entries are gone (373 is `DosQueryDOSProperty`), and `gen_api validate-doc` now checks NLS and MOUCALLS.
- **Dragging a frame's top or bottom sizing border moved it the wrong way** — the vertical direction was inverted for the N, S and corner edges of every PM frame; the drag is now the tested pure function `resized_rect`.
- **A second SDL window resized the PM desktop** — the PM renderer acted on window events without checking which window sent them, so the text window's resize after Alt+Home shrank the desktop; it now ignores other windows' events.
- **SO32DLL / TCP32DLL imports** — the Rust guest linker (`lx_link`) resolved them to ordinal 0 of DOSCALLS, and the DLL loader did not treat them as built-in modules.
- **`WARPINE_HEADLESS` was ignored for LX programs** — only the built-in CMD.EXE honoured it, so a VIO program on a terminal always opened a window although the README and the guides document the variable as forcing terminal output.
- **DLLs beside a program started by bare name were not found** — `find_dll_path` searched the executable's directory only when the path had one, so `4os2.exe` run from its own directory could not load `JPOS2DLL`; a bare name now means the current directory.
- **`WinCreateStdWindow` ignored `flClientStyle`** — the client now takes that style, so a client created with `WS_VISIBLE` (as the PM Guide's samples do) is visible to `WinIsWindowVisible` and `QWL_STYLE`.
- **`WinEnableWindow` returned the window's previous state** — the PM reference defines its result as "enabled state successfully updated"; it now returns TRUE whenever it updates the state.
- **`WinSetFocus` to the desktop window failed** — a desktop window as the new focus means no window has the focus, as the reference says; it returned FALSE.
- **`WinSetActiveWindow` posted `WM_ACTIVATE` to the frame** — it now goes to the frame's client, like the `WM_ACTIVATE` of a click or a minimize.
- **`WM_SIZE` carried 0 as the old size** after a sizing-border drag and a menu-bar change.
- **`WinMessageBox` wrapped its text in the wrong face** — measured with the process codepage's CJK face but drawn in the thread queue's.
- **`WinQueryWindowPos` left the last 8 bytes of the `SWP` unwritten** — the reserved words are cleared.
- **Guest stack sinking in modal dialogs** (`vcpu.rs`) — the modal loop built every window-procedure call from the current stack pointer, which the procedure's return leaves 16 bytes lower, so each message dispatched while a dialog or message box was open sank the guest stack by 16 bytes; a long session (a timer, mouse moves) could overflow it. Every call is now built at the same place below the `WinDlgBox` / `WinProcessDlg` return address; regression test `modal_loop_calls_do_not_sink_the_stack`.
- **Resizing the desktop window resized the focused PM window** — a leftover from one SDL window per frame: the focused frame and its client both took the desktop's size (the client then also covered the title bar) and got `WM_SIZE`. A resize of the host window now only changes the view of the desktop; PM windows keep their size and position.
- **Built-in controls after a window drag** — dragging a frame by its title bar copied the frame's desktop position into its client, whose position is relative to the frame, so afterwards controls were painted and hit-tested offset by the frame's position (clicks missed them). The drag now goes through `WindowManager::move_frame`, which moves only the frame (and keeps `FRAME_MIN_VISIBLE_W` of it on the desktop). Integration test `gui_controls_follow_a_dragged_window` replays the `pm_list_test` session in a moved window.
- **`DLGTEMPLATE` parsing** (`pm_dialog.rs`) — templates were read at guessed offsets, scanning for the next item; they are now read as `<pmwin.h>` defines them (14-byte header, 30-byte `DLGTITEM`s in tree order with their children, string pool), so control styles (`WS_TABSTOP`, `BS_DEFAULT`, ...), nested items, the focus item, the frame flags and the template codepage are honoured, and every class (`WC_MLE`, `WC_SCROLLBAR`, ...) is created instead of being turned into a static.
- **`ACCELTABLE` parsing** — the entry count was read from the codepage field.
- **Menu texts in the template's codepage** (`pm_win.rs`) — `MENUTEMPLATE` item texts were turned into characters byte by byte (Latin-1), so accented and DBCS menu items came out garbled; they are decoded with the template's codepage now (the process codepage when it gives 0), like dialog texts.
- **`WM_COMMAND` parameters** — menu and accelerator commands carried the source in the high word of mp1; as in `CMDMSG` the command is mp1 and mp2 is `MPFROM2SHORT(CMDSRC_*, fPointer)`. Shift+Tab is reported as `VK_BACKTAB`.
- **Window lookups through dialogs** — `find_frame_for_hwnd` returned the owner's frame (or a pseudo handle such as `HWND_DESKTOP`) for a dialog and its controls, and the owner window's control list included the dialog's controls.
- **Constants that did not match the OS/2 toolkit headers** (`constants.rs`) — programs are compiled against `<pmwin.h>`, `<bseerr.h>` and `<bsexcpt.h>`, so Warpine misread or sent 47 values: `WM_INITDLG` (0x3B, was 0x21), `WM_SYSCOMMAND` (0x21, was 0x0A — the value of `WM_INITDLG`), `WM_ACTIVATE`, `WM_ENABLE`, `WM_INITMENU` / `WM_MENUSELECT` / `WM_MENUEND`, the button-2 / button-3 mouse messages, `SWP_ACTIVATE` / `SWP_MINIMIZE` / `SWP_MAXIMIZE` / `SWP_RESTORE`, `HWND_DESKTOP` / `HWND_TOP` / `HWND_BOTTOM` (`HWND_FLOAT`, which PM does not have, is gone; `HWND_OBJECT` added), `FCF_STANDARD`, `SC_RESTORE`, `BN_CLICKED` / `BN_DBLCLICKED`, `BS_AUTOCHECKBOX` / `BS_RADIOBUTTON` / `BS_AUTORADIOBUTTON`, the `MB_ICON*` styles, `MBID_ENTER`, six `ERROR_*` codes (`ERROR_INVALID_FUNCTION` was 87, the value of `ERROR_INVALID_PARAMETER`; `ERROR_VIO_ROW` / `ERROR_VIO_COL` are 358 / 359), `XCPT_CONTINUE_SEARCH` (0, was 1) and 13 `XCPT_*` exception codes. A unit test, `constants_match_toolkit_headers`, now compares every constant named after a toolkit `#define` with the header when the Open Watcom headers are installed.
- **`WinQuerySysValue` and `WinQueryWindow` indices** (`pm_win.rs`) — the `SV_*` and `QW_*` numbers were wrong: `SV_CYTITLEBAR` (30), the border sizes (4 / 5, 26 / 27, 28 / 29) and `SV_CX/CYFULLSCREEN` (36 / 37) returned other values, and `WinQueryWindow` answered `QW_OWNER` for code 6 (`QW_NEXTTOP`) with the parent. They are named constants now; `WinQueryWindow` returns the owner for `QW_OWNER` (4) and also answers `QW_NEXT` / `QW_PREV` / `QW_TOP` / `QW_BOTTOM`, and `SV_CYMENU` / `SV_CX/CYBORDER` / `SV_CX/CYDLGFRAME` are reported.
- **Frame border overwritten by partial texture uploads** (`src/gui/sdl_renderer/compositor.rs`) — with the layered compositor, a client repaint of its bottom rows after the window's texture was built replaced the frame's bottom border with client pels (the client area reaches the frame's bottom edge and the border is drawn over it). It depended on timing and showed up under load (2 of 10 parallel runs). Partial uploads are now clipped to the inside of the border ring.
- **Resources of DLLs** (`managers.rs`, `lx_loader.rs`, `pm_win.rs`, `pm_bitmap.rs`, `doscalls.rs`) — only the executable's resources were indexed, and `GpiLoadBitmap`, `WinLoadString`, `WinLoadMenu`, `WinLoadAccelTable`, `WinDlgBox`, `WinLoadDlg`, `WinCreateStdWindow(FCF_MENU)`, `DosGetResource` and `DosQueryResourceSize` ignored their module handle, so a resource DLL could not be used and a DLL's resource was never found. Resources are now kept per module (`NULLHANDLE` = the executable), a loaded DLL's are registered under its handle, and its last `DosFreeModule` removes them.
- **Scripted GUI sessions on a real display** (`sdl_renderer.rs`) — host mouse, keyboard and text events are now ignored while `WARPINE_GUI_SCRIPT` runs. A real pointer event during a scripted drag moved the window to the pointer, so later drags missed the title bar and a timing run on a real display lost most of its drags.
- **Reading piped stdin hung at end of input** (`doscalls.rs`, `cmd.rs`) — in terminal mode `DosRead` of stdin retried forever when `read()` returned 0, which on a pipe, file or `/dev/null` means end of input; it now reports 0 bytes read, and the built-in CMD.EXE ends at end of input (`echo dir | warpine CMD.EXE`). A terminal still waits for a key.
- **`mciSendString("open waveaudio …")`** — a device name in place of a file was taken as a WAV file to load and failed with `MCIERR_FILE_NOT_FOUND`; device type names (optionally numbered, `waveaudio01`) now open the device. `samples/audio_test` passes again and has an integration test (`test_audio`; the test runner now gives samples an empty stdin so ones that wait for Enter finish).
- **MMPM/2 constants followed Windows MCI, not OS/2** (`mmpm.rs`) — message numbers (`MCI_PLAY` is 4, not 6, …), flags (`MCI_FROM`, `MCI_OPEN_*`, `MCI_SET_AUDIO` / `MCI_SET_VOLUME`), status items and modes, `MM_MCINOTIFY` (0x0500, not 0x0502) and its notify codes (0–3, not bit flags), and the `MCIERR_*` codes (base 5000) now match `<mcios2.h>` / `<meerror.h>`; `MCI_SET_PARMS` volume is read from `ulLevel` (+16, not +24); `MCI_OPEN` honours `MCI_OPEN_TYPE_ID` and `MCI_OPEN_ALIAS`. Real programs using `mciSendCommand` could not have worked before.
- **`mciSendString` aliases and flags** — `open … alias <name>` ignored the alias (later commands could not find the device), `wait` / `notify` swallowed the following word, and the `USHORT` return-buffer size was read as a full 32-bit slot (its undefined high half could let a reply overrun the buffer).
- **`WinStopTimer` blocked for up to a whole timer period** (`pm_win.rs`) — it joined a timer thread that only checked its stop flag after sleeping; timer threads now sleep on a condition variable that stopping signals (also faster exit).
- **A presentation space leaked on every paint** — `WinBeginPaint` created one each time and `WinEndPaint` never freed it; it now does (a PS passed to `WinBeginPaint` is kept). `WinBeginPaint` also ignored its `prclPaint` argument, leaving the caller's update rectangle uninitialised; it now reports the whole window.
- **`GpiQueryColor` / `GpiQueryBackColor` returned the resolved RGB value** instead of the colour value the application set (e.g. `CLR_RED`).
- **GPI default mix mode** (`pm_types.rs`) — new presentation spaces started with mix 6, which is `FM_AND` in `<pmgpi.h>`, not `FM_OVERPAINT` (2); the background mix now starts as `BM_LEAVEALONE`. It had no visible effect while mixes were ignored.
- **Primitives outside the window painted its edge** — boxes were drawn by clamping their corners to the window, so a box entirely outside it drew a line along the nearest edge; primitives are now clipped.
- **`WinFillRect` filled one pel too many** — the `RECTL` top and right edges are exclusive.
- **Guest coordinates near the `i32` limits** — a line or box with extreme coordinates overflowed (a panic in debug builds) or looped for billions of pels, and a huge `WinSetWindowPos` size allocated an enormous buffer. Lines are now clipped to the surface before drawing, box and text coordinates are clamped, surfaces are capped at 8192 × 8192 (`MAX_SURFACE_DIM`), and `WinSetWindowPos` / `WinCreateWindow` bound positions and sizes to ±2²⁰ (`MAX_WINDOW_COORD`) so hit tests, layout and the compositor cannot overflow.
- **Keyboard input in PM applications** (`sdl2_renderer.rs`) — shifted characters reached the application unshifted (Shift+A as `a`), non-ASCII and input-method text was dropped, and `WM_CHAR` had its flags and scan code in the wrong bit positions (CHRMSG puts flags in the low word of mp1 and the scan code in bits 24–31). Typed characters now come from SDL text input.
- **Clicks never reached built-in controls** — button-1 messages always went to the client window, so the `WC_BUTTON` `BN_CLICKED` handler was unreachable; they are now routed to the control under the pointer.
- **Static text growing bolder on repaint** (`mod.rs`) — anti-aliased label text was drawn again over itself; `WC_STATIC` now erases its rectangle first.
- **PMWIN ordinal 857 dispatched a non-existent `WinSetMenu`** (`pm_win.rs`) — 857 is `WinSetCp` in the ordinal table and PMWIN exports no `WinSetMenu`, so a program calling `WinSetCp(hmq, cp)` ran the menu-attach code with its arguments misread. The arm is now `WinSetCp`; menus are attached internally via `attach_menu_to_frame()`.
- **Wrong PMGPI / PMWIN ordinals** (`pm_gpi.rs`, `pm_win.rs`) — 21 of the 30 implemented PMGPI entry points were dispatched at ordinals that do not match the Open Watcom import libraries (`doc/os2_ordinals.md`), so real applications never reached them and hit "Unknown PMGPI Ordinal" instead: `GpiCreateLogFont` (368), `GpiDeleteSetId` (378), `GpiQueryFontMetrics` (453), `GpiQueryFonts` (586), `GpiQueryTextBox` (489), `GpiSetCharSet` (513), `GpiSetCharBox` (510), `GpiSetBackColor` (504), `GpiQueryColor` (437), `GpiQueryBackColor` (424), `GpiSetMix` (537), `GpiSetBackMix` (505), `GpiQueryCurrentPosition` (441), `GpiSetLineType` (530), `GpiSetLineWidth` (531), `GpiSetLineWidthGeom` (532), `GpiLoadFonts` (400), `GpiLoadPublicFonts` (622), `GpiUnloadPublicFonts` (623), `GpiFullArc` (393), `GpiSetArcParams` (502). Likewise `WinSetActiveWindow` (851), `WinQueryActiveWindow` (799) and `WinSubclassWindow` (929). Two new unit tests check every dispatcher arm against the ordinal table.
- **CJK regional face chosen too late** (`font.rs`, `pm_gpi.rs`) — the face order for Han ideographs was read from the process codepage when text was rasterised on the GUI thread, not when it was drawn, so text drawn under one DBCS codepage could be rendered with another region's glyph forms. `FontSpec` now carries a `CjkRegion`, pinned at the GPI call.
- **`DosSetProcessCp` rejected CP936 and CP866** (`stubs.rs`) although both are supported by the codepage layer.
- **Built-in controls erased by the client's paint** (`pm_win.rs`, `pm_types.rs`) — child controls share the window's FrameBuffer, so a client that fills its background in `WM_PAINT` painted over them and they never came back. `WinEndPaint` now repaints the window's visible built-in controls (`WindowManager::builtin_control_descendants`) before presenting.
- **Built-in control text** (`mod.rs`) — button labels are centred, static text is top-left aligned, entry-field text is vertically centred, and `WC_MLE` / `WC_LISTBOX` draw one row per line / item from the top; all text is clipped to the control with `font::fit_text` instead of overflowing it. `WC_LISTBOX` previously drew no items at all.
- **Screen size reported to guests** (`pm_win.rs`) — `SV_CXSCREEN` / `SV_CYSCREEN` returned 640×480 while the desktop is 1024×768; both now come from `constants::desktop_size()`, which the renderer also uses.
- **Every window opening at the bottom-left corner** — frames created by `WinCreateStdWindow` now cascade from the desktop's top-left corner (`default_frame_pos`).
- **Dialog layout** (`pm_win.rs`, `mod.rs`) — dialog units follow the system font's metrics instead of a fixed 8-px cell; template positions are relative to the dialog's parent window; dialogs use the standard compositor chrome (title bar, system menu, close button, dialog border) and become the active window while open.
- **Startup panic in every PM program** — `sdl2` 0.37 panicked in `poll_events` on an event type (0x207) emitted by the system SDL library; 0.38 ignores unknown event types.
- **Dialogs at half size** (`pm_win.rs`) — DLGTEMPLATE geometry is in dialog units but was used as pixels, so dialogs were tiny with truncated text; it is now converted (`dlg_units_to_px_x/y`).
- **Menu bar erased by client repaints and stale pull-downs** — see "Menu bar is frame chrome" above.
- **Title-bar text overflowing into the client area and invisible minimise button** — title text was centred for 8-px glyphs although glyphs are 16 px tall.
- **Clippy 1.100 lints** — 13 findings in existing code rewritten without behaviour change.
