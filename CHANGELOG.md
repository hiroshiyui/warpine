# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/), and this project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- **Architecture decision records** (`doc/adr/`) — 20 ADRs in Nygard format record why Warpine is built the way it is: one OS/2 process per host process, KVM execution, the near-clean-room policy, API thunks and module slots, threads on vCPUs, Unicode inside, drives on host directories, SDL3 safe-only, the own desktop compositor, fonts, VIO windows, the built-in CMD.EXE, the Rust guest toolchain, the host locale, the profile format, testing and quality gates.
- **Rectangle helpers** (new `src/loader/pm_rect.rs`) — `WinSetRect`, `WinSetRectEmpty`, `WinCopyRect`, `WinOffsetRect`, `WinInflateRect`, `WinPtInRect`, `WinIntersectRect`, `WinUnionRect`, `WinSubtractRect`, `WinIsRectEmpty`, `WinEqualRect`; they were unknown ordinals that returned FALSE.
- **`WinDrawText`** (new `src/loader/pm_drawtext.rs`) — one line of text placed in a rectangle (`DT_LEFT` / `DT_CENTER` / `DT_RIGHT`, `DT_TOP` / `DT_VCENTER` / `DT_BOTTOM`), `DT_WORDBREAK`, `DT_QUERYEXTENT`, `DT_ERASERECT`, `DT_TEXTATTRS`, `DT_MNEMONIC`, `DT_UNDERSCORE`, `DT_STRIKEOUT`, `DT_HALFTONE`, `PMERR_INVALID_FLAG`.
- **`GpiPolyLine`** — lines from the current position through a point array, drawn as one figure.
- **Scroll bars** (new `src/loader/pm_scrollbar.rs`) — `WC_SCROLLBAR` is interactive: `SBM_SETSCROLLBAR` / `SBM_SETPOS` / `SBM_QUERYPOS` / `SBM_QUERYRANGE` / `SBM_SETTHUMBSIZE`, `SBCDATA` at creation, arrows, shaft and slider dragging reported to the owner as `WM_VSCROLL` / `WM_HSCROLL` (`SB_LINE*`, `SB_PAGE*`, `SB_SLIDERTRACK`, `SB_SLIDERPOSITION`, `SB_ENDSCROLL`), repeating while held. It only drew a grey block before.
- **PM text cursor** (new `src/loader/pm_cursor.rs`, `src/gui/cursor.rs`) — `WinCreateCursor`, `WinShowCursor`, `WinDestroyCursor`, `WinQueryCursorInfo`: one cursor per message queue, solid / halftone / frame, `CURSOR_FLASH` at `SV_CURSORRATE`, inverted over the window by both compositors so painting under it leaves no trace.
- **Profiles (PMSHAPI)** (new `src/loader/profile.rs`, `src/loader/pmshapi.rs`) — `PrfOpenProfile`, `PrfCloseProfile`, `PrfQueryProfileInt` / `String` / `Size` / `Data`, `PrfWriteProfileString` / `Data`. The user and system profiles are `C:\OS2\OS2.INI` and `C:\OS2\OS2SYS.INI`, kept in Warpine's own text format (OS/2's binary INI layout is not publicly documented) and written atomically; errors through `WinGetLastError`.
- **Help Manager (HELPMGR)** (new `src/loader/helpmgr.rs`) — `WinCreateHelpInstance`, `WinDestroyHelpInstance`, `WinQueryHelpInstance`, `WinAssociateHelpInstance`, `WinLoadHelpTable`, `WinCreateHelpTable`, so programs that set up online help start; no help viewer yet (`HM_*` messages are ignored).
- **`DosExitList`** (new `src/loader/exitlist.rs`) — `EXLST_ADD` (invocation order from bits 8–15) / `EXLST_REMOVE` / `EXLST_EXIT`; the routines run lowest order first, with `TC_EXIT` (or `TC_EXCEPTION` after an unhandled exception), when the process ends by `DosExit(EXIT_PROCESS)` or thread 1 ending, while the other threads stop at their next call into Warpine. They do not run once thread 1 has ended, nor yet for a closed window, end of piped input or `DosKillProcess` from a parent.
- **Semaphore queries** — `DosResetEventSem` and `DosQueryEventSem` (events count their posts; `ERROR_ALREADY_POSTED`, `ERROR_TOO_MANY_POSTS`, `ERROR_ALREADY_RESET`), `DosQueryMutexSem`, `DosOpenMuxWaitSem`, `DosAddMuxWaitSem`, `DosQueryMuxWaitSem`, and a real `DosDeleteMuxWaitSem` (it was a stub); named semaphores keep usage counts and are deleted by their last close.
- **Critical sections** (new `src/loader/critsec.rs`) — `DosEnterCritSec` / `DosExitCritSec`: the process's other threads are held at their next call into the system until the section ends; sections nest (`ERROR_CRITSEC_OVERFLOW` / `ERROR_CRITSEC_UNDERFLOW`) and end with their thread. A thread spinning in its own code without calling the system keeps running.
- **DOS timers** (new `src/loader/dostimer.rs`) — `DosAsyncTimer`, `DosStartTimer`, `DosStopTimer` post a shared event semaphore once or repeatedly (intervals in 32 ms ticks); timers end with the process.
- **`DosSearchPath` and `DosQueryModuleName`** (new `src/loader/modpath.rs`) — search a path list or an environment variable (`SEARCH_CUR_DIRECTORY`, `SEARCH_ENVIRONMENT`, wildcards) through drive mapping like `DosOpen`; the OS/2 path of the executable, a DLL or a built-in module.
- **Memory suballocation** (new `src/loader/suballoc.rs`) — `DosSubSetMem`, `DosSubAllocMem`, `DosSubFreeMem`, `DosSubUnsetMem` (`DOSSUB_INIT` / `GROW` / `SPARSE_OBJ` / `SERIALIZE`), with the bookkeeping kept by Warpine, not in the program's memory.
- **Update rectangles** (new `src/loader/pm_paint.rs`) — each window keeps an update rectangle: `WinInvalidateRect` adds a rectangle (and children unless `WS_CLIPCHILDREN`), `WinValidateRect` and `WinQueryUpdateRect` are new, `WinBeginPaint` reports and empties it, and `WM_PAINT` comes only while something is left to paint, once per window.
- **`WinScrollWindow`** moves a window's pels, reports the uncovered area (`RGN_*`), with `SW_INVALIDATERGN` and `SW_SCROLLCHILDREN`; **`WinDrawBorder`** with `DB_PATCOPY` / `DB_PATINVERT` / `DB_DESTINVERT` / `DB_AREAMIXMODE`, `DB_INTERIOR`, `DB_AREAATTRS`, `DB_STANDARD`, `DB_DLGBORDER`.
- **Window lookups** (new `src/loader/pm_query.rs`) — `WinMapWindowPoints`, `WinWindowFromPoint`, `WinQueryDesktopWindow`, `WinQueryAnchorBlock`, `WinIsChild`, `WinQueryWindowProcess`, `WinMultWindowFromIDs`, `WinEnumDlgItem`, `WinQueryClassName`, `WinQueryClassInfo`.
- **Input state** (new `src/loader/pm_keystate.rs`) — `WinGetKeyState` (the state as of the input last read), `WinGetPhysKeyState`, `WinQueryMsgPos` / `WinQueryMsgTime`, `WinQueryPointerPos` / `WinSetPointerPos`; Shift, Ctrl, Alt, AltGr and CapsLock arrive as virtual keys in `WM_CHAR`.
- **System colours** (new `src/loader/pm_syscolor.rs`) — `WinQuerySysColor` / `WinSetSysColors` with `WM_SYSCOLORCHANGE`; title bars and `SYSCLR_*` colour values in GPI and `WinFillRect` / `WinDrawText` follow the table.
- Samples `pm_rect_text_test`, `pm_scroll_test`, `pm_profile_test`, `exitlist_test`, `semquery_test`, `xcpt_thread_test`, `kernel2_test`, `pm_paint_test` and `pm_query_test`.

### Changed
- **`gen_api validate-doc`** lists name differences acknowledged by a `# NOTE:` on the def line (such as DOSCALLS 75, `DosQueryFileMode16` / `DOS16QFILEMODE`) with their note instead of reporting them as mismatches to investigate on every pass.
- **API stub area** grows to 18432 bytes for the new PMSHAPI (`PMSHAPI_BASE` 16384) and HELPMGR (`HELPMGR_BASE` 17408) modules.
- **Built-in scroll bars look different** — arrows, shaft and slider, greyed when disabled; the `pm_controls_test` golden signatures were regenerated.

### Fixed
- **Exception handlers of other threads** — `DosSetExceptionHandler`, `DosUnsetExceptionHandler`, `DosRaiseException`, `DosUnwindException` and hardware exceptions used thread 1's TIB for every thread, so all threads shared one handler chain: an exception could reach another thread's handler. Each thread now has its own chain, in its own TIB. A handler record outside the program's memory returns `ERROR_INVALID_PARAMETER` instead of crashing Warpine.
- **Continuing after `DosRaiseException`** — a handler returning `XCPT_CONTINUE_EXECUTION` resumed the caller with EBX, ESI, EDI and EBP zeroed; the caller's registers are now kept. Sample `xcpt_thread_test`.
- **Pointer coordinates of client windows** — mouse messages to a frame's client were relative to the frame, so x was off by the border width (2 pels with a sizing border), and a window holding the capture got desktop coordinates; both are now relative to the window.
- **`QMSG` layout** — `WinGetMsg` / `WinPeekMsg` wrote the message position as two SHORTs where `QMSG.ptl` is a POINTL of two LONGs, and the time and position were always 0.
- **`WC_SPINBUTTON` atom** was 0xFFFF000F instead of 0xFFFF0020; a test now checks every `WC_*` atom against the toolkit headers.
- **`DosQuerySysInfo(QSV_TIMER_INTERVAL)`** returned 32; the value is in tenths of a millisecond, so it is now 320.
- **Wrong ordinals in the reference manual** for `DosFlatToSel`, `DosSelToFlat`, `DosSetFileLocks` and the `DosSub*` calls, and calls listed that did not exist yet.
- **Tests wrote to the user's drive C** — the integration tests and the mock loader of the unit tests used `$XDG_DATA_HOME/warpine/drive_c`; they now use temporary directories and `target/test-drive-c`.
- **Named semaphores** — a name given at creation was ignored, so opening by name never worked (and failed with `ERROR_FILE_NOT_FOUND` instead of `ERROR_SEM_NOT_FOUND`); a mutex created owned belonged to thread 1 whichever thread created it.
- **Muxwait lists of mutexes** were treated as events, so `DosWaitMuxWaitSem` never took the mutexes; `DosCreateMuxWaitSem` now checks the semaphore types, duplicates, the 64-record limit and its flags.
- **Huge GPI string counts** — `GpiCharString` / `GpiCharStringAt` used the program's count unchecked, so a count such as 0xFFFFFFFF made Warpine allocate gigabytes; they now draw at most 4096 bytes and fail for a negative count.
- **Strings at the top of the address space** — `VioWrtTTY`, `VioWrtCharStrAtt`, `UniUconvToUcs` and socket sends kept reading after the first byte outside guest memory, so an address near 4 GiB overflowed (a panic in debug builds) and a huge count meant billions of failing reads; they now stop at the first unreadable byte.

## [0.0.2] - 2026-11-18

### Added
- **System menu for PM frames** (new `src/gui/system_menu.rs`, `src/loader/pm_sysmenu.rs`) — a click on a frame's system-menu icon, Alt+Space / Shift+Esc or `WM_SYSCOMMAND(SC_SYSMENU)` opens Restore, Move, Size, Minimize, Maximize, Hide, Close and Window list, greyed by the frame's state and buttons. A choice posts `WM_SYSCOMMAND(SC_*)` with `CMDSRC_MENU` to the client, which can handle it or leave it to `WinDefWindowProc`. Sample `pm_sysmenu_test`.
- **Keyboard move and size of PM frames** (new `src/gui/frame_track.rs`) — Alt+F7 / Alt+F8 or the menu's Move / Size, then the arrow keys (sizing first picks an edge or corner), Enter to keep and Esc to restore; no Size without a sizing border or outside the normal state, no Move when maximized. The VIO window's keyboard Size picks edges the same way.
- **`WinPopupMenu`** — shows a loaded menu's items at a point (`PU_POSITIONONITEM`, `PU_SELECTITEM`) and posts `WM_COMMAND` (or `WM_SYSCOMMAND` / `WM_HELP`) to the owner; it was a stub.
- **ANSI escape sequences in text output** (new `src/loader/ansi.rs`) — `VioWrtTTY` and `DosWrite` to the screen (32- and 16-bit) interpret cursor position and movement, save / restore, `ESC[2J`, `ESC[K`, colours and wrap mode 7, also when a sequence is split across writes. On by default, as on OS/2; `VioSetAnsi(ANSI_OFF)` shows them as characters. Sample `ansi_test`.
- **`make -C samples`** (new `samples/Makefile`) builds every Open Watcom sample, so a fresh checkout can build all the binaries the integration tests run.
- **VIO window: minimize, maximize, resizing and scroll bars** (new `src/gui/vio_view.rs`) — the VIO window has minimize and maximize buttons and a sizing border. It is a view on the program's screen (the IBM reference calls a text window "a view on the larger logical video buffer"): made smaller than the screen it shows vertical and horizontal scroll bars (arrows scroll a row or column, the track a page, the thumb drags), it cannot grow past the whole screen, maximize fits it to the screen up to the desktop size, and the view follows the cursor. Alt+F5 / F7 / F8 / F9 / F10 restore, move, size, minimize and maximize it.
- **VIO window system menu and clipboard** (new `src/gui/popup_menu.rs`) — a click on the system-menu icon, Alt+Space or Shift+Esc opens a pop-up system menu with the items of IBM's OS/2 window: Restore, Move, Size, Minimize, Maximize, Hide, Close, Help, Font Size, Scroll, Mark, Copy, Copy All, Paste (Hide, Help, Font Size and Scroll greyed). Mark mode ("Marking: " in the title) marks a rectangle of cells with the mouse; Copy and Copy All put the text on the PM and host clipboard; Paste types the clipboard text into the program as keystrokes. The pop-up menu is a reusable overlay drawn by both compositors.
- **MOUCALLS mouse API** (new `src/loader/moucalls.rs`) — 20 entry points (`MouOpen`, `MouClose`, `MouReadEventQue`, `MouFlushQue`, `MouGetNumQueEl`, `MouGetPtrPos` / `MouSetPtrPos`, `MouGetNumButtons`, `MouGetNumMickeys`, `MouGetDevStatus` / `MouSetDevStatus`, `MouGetEventMask` / `MouSetEventMask`, `MouGetScaleFact` / `MouSetScaleFact`, `MouDrawPtr` / `MouRemovePtr`, `MouGetPtrShape` / `MouSetPtrShape`, `MouSynch`; ordinals from Open Watcom's `os2386.lib`, `MOUCALLS_BASE` 15360): the pointer over the VIO window (its view's scroll position included) or the full-screen text window reaches `MouReadEventQue` in text cells; full screen, the text-mode pointer is drawn after `MouDrawPtr`. New sample `mou_test` (36 checks) run windowed and full screen.
- **True full screen and Alt+Home** (new `src/gui/vio_switch.rs`) — the full-screen display of a VIO program is a desktop-full-screen window with the text screen scaled by whole multiples and letterboxed in black (an ordinary window when full screen is refused), and Alt+Home switches a window-compatible program between its PM window and full screen while it keeps running. Each display's window is hidden and reused rather than destroyed, so switching does not leak.
- **VIO programs in a window on the PM desktop** (new `src/gui/vio_window.rs`, `src/loader/vio_frame.rs`) — on OS/2 a window-compatible text-mode program runs either full screen or in an "OS/2 window"; Warpine always gave it a separate 640 × 400 text window. A VIO program on a terminal now runs by default in a frame on the PM desktop (title bar, system-menu icon, border; the size of its text screen, following `VioSetMode`), drawn from the VIO buffer with the text window's cell renderer; keys typed while the frame is active go to the program's keyboard queue (`KbdCharIn`), and the close button or a double click on the system-menu icon ends the program. `WARPINE_VIO=fullscreen` keeps the separate text window, which a program marked "incompatible with PM windowing" in its LX module flags always gets (`LxHeader::app_type`). The built-in CMD.EXE follows the same rule. Integration test `vio_program_runs_in_a_pm_window_by_default`.
- **Scripted sessions in the text window** (`src/gui/text_renderer.rs`) — the VGA text window of VIO programs replays a `WARPINE_GUI_SCRIPT` like the PM desktop: `key` and `text` steps type into the program, `dump PATH` writes the 640 × 400 frame as a PPM, `quit` ends the session, and host keystrokes are ignored meanwhile. The README's 4OS2 screenshot is captured this way; integration test `text_mode_window_replays_a_gui_script_and_dumps_the_screen` (needs `script` from util-linux for a pseudo-terminal, since the text window opens only on a terminal).
- **Window tree and window-pointer calls** (new `src/loader/pm_window.rs`) — `WinIsWindowVisible` (775: TRUE when the window and all its parents have `WS_VISIBLE`), `WinQueryWindowTextLength` (842: the text's bytes in the queue codepage, without the null), `WinSetParent` (865: to another window, `HWND_DESKTOP` or `HWND_OBJECT`; a frame joins or leaves the Z-order; a descendant as the new parent fails), `WinSetOwner` (864; NULLHANDLE disowns), `WinQueryWindowPtr` / `WinSetWindowPtr` (839 / 876: the application's window words, shared with `WinQueryWindowULong`, and `QWP_PFNWP`, the window procedure) — they fell through to "Unknown PMWIN ordinal". New sample `pm_window_test` (36 checks).
- **Mouse pointers** (new `src/loader/pm_pointer.rs`, `src/gui/pointer.rs`) — `WinQuerySysPointer` returns stable handles for the `SPTR_*` system pointers (`fCopy` makes a copy the caller destroys); `WinSetPointer` / `WinQueryPointer` change and report the pointer, and the host mouse cursor follows (system pointers become SDL system cursors, the message-box icons and loaded pointers colour cursors; NULLHANDLE hides it); `WinShowPointer` keeps PM's display level (`SV_POINTERLEVEL`); `WinLoadPointer` reads `RT_POINTER` resources — black-and-white and colour pointers and icons, both header layouts, bitmap arrays (the 32 × 32 entry is chosen), every offset bounds-checked — and `WinDestroyPointer` frees them; `WinDefWindowProc` sets the arrow on `WM_MOUSEMOVE`; `SV_CXPOINTER` / `SV_CYPOINTER` / `SV_MOUSEPRESENT`. New sample `pm_pointer_test` (42 checks; its `.ptr` files are written by `make_ptr.py` from the documented format).
- **Button messages** (`pm_button.rs`) — `BM_CLICK` (an up-click clicks the button as a mouse click would; a down-click only highlights it), `BM_SETHILITE` / `BM_QUERYHILITE` (a highlighted push button is drawn pressed; only push buttons answer the query, as documented) and `BM_SETDEFAULT` (sets or clears `BS_DEFAULT` on push and user buttons, which Enter in a dialog then follows). `pm_button_test` grows to 54 checks.
- **A focus mark on list boxes** — a focused list box outlines its cursor item with a dashed rectangle in every selection mode (it was drawn for multiple- and extended-selection lists only, as a solid box).
- **Hide button, activation on minimize, `WM_SIZE` on resize** (`pm_minmax.rs`) — `FCF_HIDEBUTTON` / `FCF_HIDEMAX` draw a hide button whose click posts `WM_SYSCOMMAND(SC_HIDE)`, and `WinDefWindowProc` hides the frame with the frames it owns. Minimizing or hiding the active frame activates the next visible, enabled frame in the Z-order (`WM_ACTIVATE` FALSE to the old frame's client, then TRUE to the new one's). `WinSetWindowPos(SWP_SIZE)` sends `WM_SIZE` with the old and new size to the window, or to a frame's client (it sent nothing). `WinQueryWindowPos` reports `SWP_MINIMIZE` / `SWP_MAXIMIZE`, and `SWP_ACTIVATE` / `SWP_DEACTIVATE` for frames. `pm_minmax_test` grows to 60 checks.
- **More `WinGetLastError` codes** (`pm_error.rs`) — 28 more PMWIN calls record `PMERR_INVALID_HWND` for a handle that is no window (window state, rectangle and position, window words, enabling, invalidating and updating, focus / active window / capture, `WinGetPS` / `WinBeginPaint` / `WinOpenWindowDC`, the dialog-item calls, `WinCreateWindow`'s parent and owner, the `WinGetMsg` / `WinPeekMsg` window filters); `PMERR_PARAMETER_OUT_OF_RANGE` for a bad `WinQueryWindow` code and window-word indices below `QWL_MIN` / `QWS_MIN` or past the class's `cbWindowData`; `PMERR_INVALID_FLAG` for unknown `WinPeekMsg` flags; `PMERR_INVALID_HACCEL` for `WinSetAccelTable`. `pm_error_test` grows to 113 checks.
- **`SV_CURSORRATE` and `WinSetSysValue`** — `WinQuerySysValue(SV_CURSORRATE)` reports the caret blink rate in milliseconds, and the new `WinSetSysValue` (873) changes it, which the caret blink follows.
- **Input-method window at the caret** — the host input-method window (for composing CJK text) is placed at the caret of the focused entry field or MLE (`SDL_SetTextInputArea`).
- **Scrolling while the pointer rests past the edge** — dragging a selection out of an entry field, MLE or list box and holding the pointer still keeps scrolling, a row every 100 ms (`WM_TIMER(TID_SCROLL)`; it scrolled only while the pointer moved).
- **Frame minimize, maximize and restore** (new `src/loader/pm_minmax.rs`) — the min/max buttons used to post `WM_SYSCOMMAND` that nothing handled. `WinDefWindowProc` now carries out `SC_MINIMIZE` / `SC_MAXIMIZE` / `SC_RESTORE` for frames with minimize or maximize buttons (PM's `FID_MINMAX`), and `WinSetWindowPos` takes `SWP_MINIMIZE` / `SWP_MAXIMIZE` / `SWP_RESTORE` and sets `WS_MINIMIZED` / `WS_MAXIMIZED` (readable through `WinQueryWindowULong(QWL_STYLE)`). The client gets `WM_MINMAXFRAME` first, synchronously with an `SWP` on the guest stack (a TRUE reply cancels), and `WM_SIZE` after every change. The restore position lives in `QWS_XRESTORE`…`QWS_CYRESTORE` and the icon position in `QWS_XMINIMIZE` / `QWS_YMINIMIZE` (`WinQueryWindowUShort` / `WinSetWindowUShort`). A maximized frame covers the desktop with its border just outside it, and its maximize button becomes a restore button; a minimized frame is a small title bar in an icon area at the bottom of the desktop, which a double click restores; frames it owns are hidden meanwhile. Alt+F5 / Alt+F9 / Alt+F10 join Alt+F4 in the system accelerators, a title-bar double click maximizes or restores, and a double click on the system-menu icon closes the window. New sample `pm_minmax_test` (39 checks) and golden `pm_minmax_test`.
- **`WM_DESTROY`** (new `src/loader/pm_destroy.rs`) — `WinDestroyWindow` removed windows silently. It now hides the window and sends `WM_DESTROY` synchronously, first to the window and then to its children (each before its own children) while all still exist, as the `WinDestroyWindow` reference describes; only then are they removed. A frame also destroys the windows it and its descendants own; the focus leaves a destroyed frame; `WinGetPS` presentation spaces of destroyed windows are freed and `GpiCreatePS` ones disassociated; destroying another thread's window fails; a `WinDestroyWindow` from a `WM_DESTROY` handler never sends a window the message twice. `WinDlgBox` destroys its dialog the same way before it returns. New sample `pm_destroy_test` (23 checks).
- **Check boxes and radio buttons** (new `src/loader/pm_button.rs`) — buttons had no check state. `BM_SETCHECK` / `BM_QUERYCHECK` / `BM_QUERYCHECKINDEX` work; auto check boxes toggle, auto three-state buttons cycle and auto-radio buttons uncheck the other auto-radio buttons of their group when selected; every check box and radio button notifies `WM_CONTROL(BN_CLICKED)`. In dialogs the arrow keys check the auto-radio button they move to (not with `BS_NOCURSORSELECT`), and Tab enters a radio group on its checked button. They are drawn with their own indicators (tick, indeterminate square, dot) and a focus mark. New sample `pm_button_test` (32 checks) and golden `pm_button_test`.
- **`WinGetLastError`** (new `src/loader/pm_error.rs`) — it always returned 0. It now returns the calling thread's last PM error (severity in the high word, the `PMERR_*` code in the low word) and resets it, as the reference says. Recorded so far: `PMERR_MSG_QUEUE_ALREADY_EXISTS` (a second `WinCreateMsgQueue`), `PMERR_INVALID_HMQ` (`WinDestroyMsgQueue` of another thread's or an unknown queue), `PMERR_NO_MSG_QUEUE` (`WinGetMsg` / `WinPeekMsg` without a queue) and `PMERR_INVALID_HWND` (`WinDestroyWindow`, `WinSetWindowPos`, `WinSetWindowText`, `WinQueryWindowText`, `WinWindowFromID`, `WinPostMsg`, `WinSendMsg`). New sample `pm_error_test` (36 checks).
- **Message-box icons, Help and Close** (`pm_msgbox.rs`) — the `MB_ICONHAND` / `MB_ERROR` / `MB_CRITICAL`, `MB_ICONASTERISK` / `MB_INFORMATION`, `MB_ICONEXCLAMATION` / `MB_WARNING` and `MB_ICONQUESTION` / `MB_QUERY` styles draw a 32 × 32 pictogram of Warpine's own, after the reference's descriptions, left of the text; `MB_HELP` adds a Help button that sends `WM_HELP` to the message box, which stays open. `pm_msgbox_test` grows to five boxes and 9 checks.
- **Type-ahead routing** (new `src/loader/pm_input.rs`) — the GUI thread chose a keystroke's window when the key arrived, so keys typed while a program was busy went to the window that had the focus *then*, even if handling an earlier key moved the focus. Keyboard and pointer input now waits in one system input queue, and `WinGetMsg` / `WinPeekMsg` / the modal dialog loop route the oldest event when they read it — after the thread's posted messages, as in PM: a key to the focus window of that moment, a typed character encoded in that window's queue codepage. An event for another thread's window waits for that thread and holds back the events behind it. Before a click activates another frame or takes the focus from a control, the keys still waiting are fixed to the window they were typed for. New sample `pm_typeahead_test` (4 checks; the previous build fails 3 of them) and integration test `gui_pm_typeahead_test_routes_keys_when_they_are_read`.
- **Word wrap, multi-select list boxes, `LN_ENTER`, double-clicks and a blinking caret** (`pm_edit.rs`, `pm_list.rs`, `pm_controls.rs`, `sdl_renderer.rs`) — an MLE with `MLS_WORDWRAP` (or `MLM_SETWRAP`, queried with `MLM_QUERYWRAP`) breaks its lines into rows that fit, after the spaces following the last word that fits (a longer word breaks between characters); Home / End / Up / Down / PageUp / PageDown and clicks work on rows. List boxes select in three modes (`pm_list::ListSelection`): one item (default), `LS_MULTIPLESEL` (a click or Space toggles one item, the cursor keys move only the cursor, outlined while focused) and `LS_EXTENDEDSEL` (Shift+click / Shift+arrows select the range from the anchor, Ctrl+click toggles, dragging extends); `LM_SELECTITEM` adds to or removes from a multiple selection, `LM_QUERYSELECTION` walks it from `LIT_FIRST`, and `LIT_CURSOR` asks for the cursor item. The second press of a double click arrives as `WM_BUTTONnDBLCLK` (built-in controls and the menu bar treat it as a press); a double-clicked item or Enter in a list box sends `LN_ENTER` (Enter then still goes to the owner, so a dialog's default button works). The focused entry field or MLE blinks its caret every `CARET_BLINK_MS` (500 ms) through `WM_TIMER(TID_CURSOR)`, which the GUI loop posts (one pending at a time) and the control handles; input shows the caret at once; scripted sessions do not blink. ### Changed
- **A single click on a frame's system-menu icon opens the system menu** instead of starting a drag; a double click still closes the frame.
- **Country and codepage follow the host locale** — a program now starts with the OS/2 country code and process codepage of the host locale, as on an OS/2 installation in that language (`ja_JP` → country 81 / CP932, `de_DE` → 49 / CP850, `C` → 1 / CP437), instead of always 1 / CP437; the VIO screen and new message queues follow it. `WARPINE_COUNTRY` and `WARPINE_CODEPAGE` override it (e.g. `WARPINE_CODEPAGE=437` for programs that draw with CP437 box characters). The fixed US setting had been a workaround for the Watcom C runtime hanging at start-up with non-US countries, which the NLS ordinal fix removed. The integration tests and the screenshot helper pin 1 / 437.
- **Calls with a handle that is no window now fail** — `WinShowWindow`, `WinUpdateWindow`, `WinInvalidateRect`, `WinStopTimer`, `WinSetCapture`, `WinSetDlgItemText`, `WinDismissDlg`, `WinSetAccelTable`, `WinSetWindowULong` / `WinSetWindowUShort`, `WinQueryWindowRect` (it reported 640 × 480), `WinQueryWindowPos` and `WinEnableWindow` returned TRUE for such a handle; they return FALSE, and `WinCreateWindow` with a bad parent creates nothing, as the PM reference says.
- **Caret positions, clicks and word wrap are measured in the queue's CJK face** — text controls measured with the process codepage's face while drawing in their queue's; the two now agree.
- **Invalid window handles** — `WinSetWindowPos`, `WinSetWindowText` and `WinPostMsg` now return FALSE for a handle that is not a window (recording `PMERR_INVALID_HWND`); `WinPostMsg` used to drop such a message into another queue.
- **Closing a message box** — the close button and Alt+F4 end a message box with `MBID_CANCEL` even when it has no Cancel button ("whether or not a cancel button existed", the `WinMessageBox` reference); Esc still cancels only a box with a Cancel button.
- **CJK face of control, title and menu text** (`mod.rs` `Painter`, `surface.rs`, `sdl_renderer.rs`) — built-in controls, title bars and menus drew CJK characters in the face of the process codepage, so a window whose queue was set to another codepage with `WinSetCp` (e.g. CP949 in a CP932 process) showed its Hangul and hanja in the Japanese face. They now use the face of the window's (or frame's) queue codepage, as GPI text already did with its presentation space's.
- **Message order in a queue** (`pm_input.rs`) — `WinGetMsg`, `WinPeekMsg` and the modal dialog loop handed out a queue's messages in posting order, so a `WM_TIMER` or `WM_PAINT` could come before a later posted message or before input. They now follow the PM Reference: posted messages, then keyboard and mouse input, then `WM_PAINT`, then `WM_TIMER` (`WindowManager::next_queued`, one function for all three). `pm_typeahead_test` checks the order from the guest (5 checks; the previous build fails the new one).
- **The pre-commit hook lints the test code** — `githooks/pre-commit` ran only `cargo test`, although the README said it also ran clippy; it now runs `cargo clippy --all-targets -- -D warnings` as well, so lints in tests fail the commit. The 26 lints already in test code are fixed.
- **`WinMessageBox` is a modal PM dialog** (`pm_msgbox.rs`) — it used SDL's native message box on the GUI thread, which froze the whole desktop (every window, repaints, timers) until it was closed. It is now a dialog built in memory — the caption, the text wrapped at word boundaries, the push buttons of the `MB_*` set with the `MB_DEFBUTTON*` default — centred on the desktop and run by the `WinDlgBox` modal loop: only its owner's frame is disabled, and the owner's window procedure keeps getting its messages. A push button returns its `MBID_*`; Esc and closing cancel a box that has a Cancel button. Scripted sessions can answer message boxes. New sample `pm_msgbox_test` (7 checks) and golden `pm_msgbox_test`; `GUIMessage::ShowMessageBox` is gone.
- **Message queues follow the PM reference** (`pm_win.rs`, `pm_types.rs`) — `WinDestroyMsgQueue` was a stub that kept the queue; it now destroys the calling thread's own queue and its pending messages (FALSE for another thread's queue or an invalid handle), after which the thread can create a new one. `WinCreateMsgQueue` returns `NULLHANDLE` when the thread already has a queue, and `WinPostMsg` returns FALSE when there is no queue to post to. `pm_list_test` checks the lifecycle (17 checks).
- **Menu bars are shown through `WM_UPDATEFRAME`** (`pm_win.rs`) — `WinLoadMenu` used to attach the new menu to the frame at once and `WinCreateMenu` never did. Following the PM reference, both now create the menu as an `FID_MENU` child owned by the frame (found with `WinWindowFromID(frame, FID_MENU)`), and the frame shows its topmost `FID_MENU` menu when sent `WM_UPDATEFRAME(FCF_MENU)` (handled in `WinDefWindowProc`). Destroying the shown menu takes the bar away. `FCF_MENU` menus are `FID_MENU` windows too. `pm_menu_dlg_test` replaces its menu bar that way (9 checks, now asserted by `gui_menu_dlg_test_replaces_the_menu_bar`).
- **SDL3 instead of SDL2, with no `unsafe`** (`Cargo.toml`, `src/gui/`; `sdl2_renderer.rs` / `Sdl2Renderer` / `Sdl2TextRenderer` renamed to `sdl_renderer.rs` / `SdlRenderer` / `SdlTextRenderer`, and the `sdl2` names in the console and keyboard code to `sdl`; `build.rs` no longer looks up SDL2 with pkg-config) — the PM desktop and the VGA text window use sdl3-rs 0.22 through its safe API only; `src/gui` and `mmpm.rs` are `#![forbid(unsafe_code)]`. The `unsafe_textures` feature (which dropped the texture-lifetime check) is gone, as are the raw calls for the wake-up event, mouse capture and the byte view of the desktop buffer. Building needs `libsdl3-dev` instead of `libsdl2-dev`. GUI output is unchanged (golden tests) and composite times are unchanged; checked by hand on X11 and Wayland (input, clipboard, window management, audible audio).
- **Audio plays on the main thread** (new `src/gui/audio.rs`) — SDL3 audio objects cannot leave the main thread, so MMPM/2 and `DosBeep` hand PCM data to an `AudioService` and the PM / VGA loop plays it through SDL3 audio streams, which also convert formats (the SDL2 conversion code is gone). WAV files are decoded in Rust (uncompressed PCM and float; compressed WAVs, which `SDL_LoadWAV` accepted, are refused). `MCI_SET` volume changes now reach a playing sound. Headless runs have no audio output.
- **PM drawing is rasterised on the calling thread** (new `src/gui/surface.rs`) — GPI primitives, `WinFillRect` and built-in controls draw straight into the shared surface of their frame (`WindowManager::surfaces`) instead of sending one `GUIMessage` per primitive to the GUI thread, which now only composites. The pixels exist when the call returns, which `GpiQueryPel` and destination-dependent mixes need; drawing outside `WinBeginPaint` / `WinEndPaint` now shows up without waiting for another repaint. `GUIMessage` keeps only clipboard, mouse-capture and message-box requests. Guest-side `pm_bench` rates are unchanged for boxes and lines (~28 µs per call) and about 13 % lower for text, which is now rasterised inside the call.
- **The PM compositor redraws only what changed** (`sdl2_renderer.rs`, new `src/gui/damage.rs`) — the desktop buffer is kept between frames; damage comes from dirty windows (mapped to their frame) and frames that moved, changed chrome or disappeared, and only those rectangles are redrawn and uploaded (`Texture::update`). Frames hidden by an opaque frame above are skipped, pixels are copied row by row, and title bars, menu bars and pull-downs are pre-rendered per frame and re-rendered only when they change. On SDL's `dummy` driver (release build, 1024×768) a composite takes 0.37 ms instead of 0.69 ms during `pm_bench` and 0.61 ms instead of 0.90 ms while dragging a window, which also composites only when the pointer moves (121 instead of 182 composites in 5 s). Frame statistics now report the share of the desktop redrawn.
- **Per-thread glyph cache** (`font.rs`) — each character's face, advance and coverage bitmap are cached per thread; drawing and measuring text no longer lock a global cache or clone an `Arc` per glyph, nor resolve the face again.
- **Resizing keeps window content** — `FrameBuffer::resize` keeps the bottom-left part of the old picture instead of blanking the window until the application repaints.
- **PM event loop blocks instead of polling** (`renderer.rs`, `message.rs`, `sdl2_renderer.rs`, `pm_types.rs`) — the GUI thread used to sleep 8 ms per pass (up to 8 ms added latency, ~125 wake-ups a second when idle) and read the host clipboard on every pass. It now blocks until input, a queued GUI message, a window marked dirty, the next frame or the next scripted step (`GuiWake`, woken by `GUISender::send` and `WindowManager::mark_dirty`); idle, it wakes 10 times a second. `PresentBuffer` no longer composites immediately: composites are coalesced to at most one per 16 ms frame. The host clipboard is read at start-up and on clipboard-update and focus-gained events. On SDL's `dummy` driver an idle session uses about half the CPU it did.
- **`create_gui_channel` returns a `GUIReceiver`** and `PmRenderer::frame_sleep` is replaced by `install_waker` + `wait_for_work`.
